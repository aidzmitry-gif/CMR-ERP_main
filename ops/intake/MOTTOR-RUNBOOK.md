`systemctl stop crm-mottor-intake.service`. Сохранить очередь и конфигурацию:
повторная инициализация теряет границу и доказательства доставки.

## Поведение и ограничения

API читается с фильтром сайта и даты, проверяется домен и время каждой строки.
Каждый опрос сверяет весь период с зафиксированной границы запуска; уникальный
Mottor ID отсекает повторы. Это включает заявки, которые API показал с задержкой.
Порядок ID должен строго возрастать, иначе курсор не продвигается.
Индивидуальный ответ API сохраняется в очереди полностью, включая form/history/cart.
В CRM передаются контакт, номер заявки и исходные данные в сообщении с маркером
`[mottor:1191119:ID]`. Файлы по ссылкам не скачиваются: ссылки остаются в исходном
документе. Данные UTM пока не разобраны в отдельные поля отчётности CRM.

Состояния: `pending` — ожидает отправки; `accepted` — CRM подтвердила приём события;
`review` — нужна сверка слишком большого документа;
`sending`/`uncertain` — результат POST неизвестен. Последние три состояния дают
ненулевой код службы и видны в журнале. Отдельное уведомление оператору пока не
настроено. Ошибка чтения источника оставляет курсор и уже сохранённые записи;
следующий запуск повторяет чтение. Очередь защищена межпроцессным flock.

Не повторять `uncertain` вслепую: проверить маркер в CRM и событии приёма.
Если запись в CRM подтверждена, отметить доставку принятой; если доказано,
что события и лида нет, вернуть в `pending`. CLI для сверки пока отсутствует.
Это намеренная остановка неопределённых отправок, а не гарантия автоматического
восстановления при любой ошибке сети.

Существующая CRM объединяет новые обращения того же открытого контакта/компании
в один лид, добавляя текст. Сборщик отправляет разные Mottor ID по отдельности,
но не меняет это поведение CRM. Для Legat такой приёмник напрямую не подходит:
тендеры/лоты должны иметь собственную идентичность, иначе общий отправитель
склеит разные закупки. Почтовый разборщик Legat ещё не подключён.

# Подготовленное переключение на intake/v1 (ещё не выполнено)

`mottor_receipts.py` использует существующую очередь и сохраняет неизменяемый
конверт через `receipt_queue.py`. POST можно безопасно повторять после сетевого
сбоя; только отдельный GET с совпадающими identity, canonical SHA256 и lead_id
подтверждает доставку. Canonical SHA проверен по fixture настоящего приёмника.
Даже ошибка очередной страницы Mottor не блокирует отправку уже сохранённых заявок.

Переключать ExecStart на `mottor_receipts.py` можно после выкладки проверенного
receiver и миграции 0113. Конфигурация user_id/api_key/crm_token остаётся прежней.
Старые accepted/sending/uncertain записи автоматически не переотправляются:
legacy endpoint не имел receipt. Два accepted источника уже сверены отдельно
с лидами, в том числе реальная форма 32415691 → lead 8.

До переключения действующая служба продолжает использовать `mottor_bridge.py`.
Ни наличие этого файла, ни native unit-тесты не подтверждают production cutover.
