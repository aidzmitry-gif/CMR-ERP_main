B. Как AI-функции кокпита раскладываются по моделям

экономия + качество
Принцип из canon MODEL-TIERING: качество там, где цена ошибки высока; экономия — на механике. Есть дешёвый оракул / результат легко проверить → Sonnet или ниже. Нет оракула, деньги/обязательства → Opus. В проде это ставится в единый LLMGateway.complete(kind=…) — точка тиринг-роутинга уже спроектирована, правило маппинга надо добавить.
AI-функцияМодель/тирПочему
Скоринг «горячий/холодный» (само число) правила Оракул уже есть: детерминированный движок score_lead, балл по заполненности профиля и каналу. LLM тут не решает.
Объяснение скоринга текстом Sonnet Генеративный текст малой сложности, дёшево проверяем. Так уже сделано в modules/leads/ai.py (kind="qualify").
Извлечение полей из письма/заявки (кол-во, сроки, контакты) Sonnet + JSON-схема Структурное извлечение; качество даёт не модель, а валидация по схеме — при провале retry/эскалация. Шаблон — connectors/insights.py.
Разбор тендерного PDF/XLSX (ТЗ, позиции, сроки, бюджет) Sonnet + JSON-схема Длинный документ, нужна аккуратность; гейт = схема, цена ошибки средняя.
Рекомендация продавца (матч гео/продукт/загрузка) + выбор воронки правила Справочник + пороги (route_lead/choose_funnel уже есть). LLM не нужен, локально и мгновенно.
Черновик уточняющего письма клиенту Sonnet + human-in-the-loop Текст наружу; человек вычитывает перед отправкой (дешёвый оракул). Никогда не автослать.
Суммаризация переписки/истории лида Sonnet Сжатие, риск низкий (kind="summary").
Глубокий разбор тендера: юр.условия, штрафы, риски, маржинальность Opus Деньги и обязательства, нет дешёвого оракула. Только в полной карточке, по кнопке, не в потоке. В кокпите Opus НЕ нужен.

Вывод: в самом кокпите Opus не нужен: почти всё — детерминированные правила (оракул) + Sonnet под гейтом (JSON-схема для извлечения, human-in-the-loop для писем клиенту). Opus держим на редкий тяжёлый разбор тендера в полной карточке. Это и есть экономия: локальная qwen/правила на потоке, Sonnet точечно, Opus почти никогда.
Как собран этот анализ (та же дисциплина): разведку кода (бэк лидов, фронт, интейк, канон тиринга) вели 4 параллельных агента на Sonnet — дёшево и проверяемо. РОП-синтез, дизайн-решения и раскладку по моделям держал Opus — высокая цена ошибки. Сборку HTML по готовому спеку (оракул — дословные токены эталона) сделал Sonnet.
