# Автоматические курсы НБРБ

База расчёта — BYN. Источник: https://www.nbrb.by/apihelp/exrates.htm,
`https://api.nbrb.by/exrates/rates/{ISO}?parammode=2&ondate=YYYY-MM-DD`.
Сумма BYN = исходная сумма × `Cur_OfficialRate` / `Cur_Scale`.
Расчёт Decimal, финальное округление до копейки ROUND_HALF_UP. Надбавка 10%
не применяется к финансовым операциям; отдельный плановый буфер закупок сохранён.

## Подключённые операции

- Создание платежа: `POST /finance/payments`, поля `currency`, `operation_date`.
  `amount` на входе — исходная валюта; на выходе `amount` — BYN,
  `amount_orig` и `currency` сохраняют оригинал. Для не-BYN дата обязательна.
- События выставления счёта, фрахта, возврата фрахта и landed cost:
  `operation_date` / `document_date`, иначе дата создания исходного события
  (UTC → Europe/Minsk). Повторная доставка не выбирает сегодняшний курс.
- Банковские зачисления: исходная сумма и валюта остаются в банковском журнале;
  автоматическое и ручное распределение используют BYN на дату банка.
- Частичные поступления принимают `currency` и `operation_date` и сохраняют
  снимок пересчёта. Начальные валютные остатки в прогнозе переводятся в BYN
  на `opening_at`, без смешения валют в итоговой сумме.
- Закупочный `POST /procurement/cost-estimate`: курсы USD/RUB/CNY берутся
  автоматически, клиентские валютные ставки больше не определяют результат.
  `operation_date` необязательна, по умолчанию сегодня в Минске;
  ответ содержит `fx_quotes`. Комиссии, фрахт и плановый буфер остаются входными данными.
- Переключатель валюты CRM получает курс с backend. Если курса нет,
  показывает «Курс недоступен», без подстановки 1:1 или demo.

Общий API для остальных потребителей:
`GET /system/fx/USD?on=2026-09-01` и
`POST /system/fx/convert` с `{"amount":"100","currency":"USD","on":"2026-09-01"}`.
Доступ — пользователям с доступом к ERP; гостю 403.

## Обновление и история

Фоновая задача запускается с приложением, обновляет активные валюты справочника
и BYN/USD/EUR/RUB/CNY/PLN, повторяет проверку каждый час независимо от relay.
Другие валюты НБРБ доступны по ISO-коду по запросу. Поддерживаются даты
с 01.07.2016 до сегодня (граница BYN после деноминации).

В существующем append-only AuditLog сохраняется точный снимок исходного курса,
номинал и дата (`currency.nbrb.quote`), а при применении — `finance.fx.applied`.
Используется существующая таблица, без новых миграций. PostgreSQL advisory locks
сериализуют одновременную загрузку и обновление справочника. UI-справочник SCD2
хранит шесть знаков; денежный расчёт использует исходный курс и номинал из снимка.
Конфликт ручного курса за ту же дату регистрируется как ошибка, без перезаписи.

При отсутствии точного курса нет подстановки соседней даты, demo или 1:1.
API возвращает ошибку; финансовое событие остаётся необработанным и может
повториться после восстановления соединения. Успешно сохранённые операции
автоматически не переоцениваются.

## Границы

Это интеграция официального пересчёта действующего main, а не автоматическая
переоценка остатков/курсовых разниц или замена курса коммерческой сделки банка.
Модули и документы, у которых контракт суммы уже BYN, сохраняют этот контракт.
Новый бухгалтерский модуль в параллельной незавершённой рабочей копии
`crm-accounting-20260909` не является частью main и не изменён этой веткой.
Его проводки должны использовать общий сервис при интеграции того модуля.
Старые операции, рассчитанные demo-курсами, требуют отдельной сверки; массового
пересчёта исторических данных нет.

При росте журнала следует выделить индексированный реестр снимков курса
отдельной согласованной миграцией; сейчас lookup использует существующий AuditLog.
