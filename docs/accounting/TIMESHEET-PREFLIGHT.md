# Предварительная проверка табеля XLSX

Для кандидата на источник часов сначала запустите только читающую проверку:

```powershell
python scripts/accounting_timesheet_preflight.py 'D:\6 Проекты\CRM ERP\Табель работчего времени июнь2026.xlsx' --month 2026-06
```

Код выхода `0` означает, что **структура этого шаблона** согласована: период в названии единственного листа, последовательность дней с `E8`, месячные часы и рабочие дни в соседних колонках, полная формула часов (включая общие формулы Excel), кэшированная сумма всех числовых дневных часов, уникальные табельные номера. Код `1` означает найденные расхождения; `2` — файл или формат нельзя проверить. JSON содержит SHA-256 и только номера строк/типы ошибок, без ФИО и табельных номеров. Файл не изменяется.

Текстовые дневные коды показываются только суммарным предупреждением и **не превращаются в часы**. Даже при коде `0` поле `payroll_approved` остаётся `false`: нужны подтверждённые значения кодов, принадлежность юрлицу, однозначная привязка строк к договорам, проверка первичного документа и применимых правил бухгалтером. Результат этой проверки нельзя импортировать как начисление или использовать для проведения.

Для уже сохранённого файла табеля бухгалтер открывает `GET /accounting/organizations/{org_id}/payroll-evidence-files/{file_id}/timesheet-preflight`. Сервер повторно сверяет приватные байты с квитанцией и возвращает `structure_checked`, `structure_failed`, `uncheckable` или `manual_source`. Экран расчётного листа показывает статус XLSX и строки с ошибками. Ошибочный XLSX можно хранить и просматривать, но новая арифметическая проверка главбуха по нему отклоняется сервером. Для исправного XLSX бухгалтер выбирает номер строки работника: сервер сравнивает введённые часы с суммой числовых ячеек выбранной строки за указанный отрезок работы. Номер строки, результат сверки и количество дней с нерасшифрованными текстовыми кодами сохраняются в основании черновика. PDF и другие допустимые документы получают статус `manual_source`: их содержание остаётся на ручной проверке, автоматическая проверка структуры им не приписывается. Даже `structure_checked` и совпадение часов не подтверждают принадлежность строки конкретному договору, значение кодов или правильность начисления.
