# CRM-ACC-001: контролируемый запуск backend-кандидата

Статус: **локальная проверка, не серверный выпуск**. Точный исходник
`aa59bc61fb398333acb61751e43963af177e46d3` материализован из Git blobs
корня и десяти закреплённых модулей: 2616/2616 blob-хешей совпали; в контекст
сборки не попали `.env`, `.git` и незатреканный `reports/CRM-ACC-001/`.
Собран Linux/amd64 image
`sha256:d943ab510dbee847e41f9ddeeb1d50ce9e91639df80c5cfb16076e687c2468a8`
(122383834 байта). Ни образ, ни приложение на сервер не отправлялись.

Проверка исправила два реальных дефекта предыдущего локального кандидата:
`pypdf` использовался в модуле продаж, но был только dev-зависимостью и
отсутствовал в Docker-образе; startup-лог БД печатал строку подключения
вместе с паролем. В новом образе импорт `pypdf`/приложения прошёл, а
синтетический пароль отсутствует в startup-логе.

На отдельной синтетической PostgreSQL 16 во внутренней Docker-сети без
публикации портов backend запущен с `AIOS_SKIP_AUTOMIGRATE=1` и
`AIOS_DISABLE_ASYNC_WRITERS=1`. Контейнер имел read-only root filesystem;
`/health` вернул 200, startup-лог подтвердил пропуск миграции и фоновых
процессов. `alembic_version` после этого запуска отсутствовала. Затем тем же
image отдельная явная команда `alembic upgrade head` на **пустой временной**
БД завершилась успешно; `alembic current` и SQL дали `0176`.

Локальные проверки исходников: `tests/test_lifespan.py` и
`tests/test_background_intake_relay.py` — 5 passed; Ruff, compileall и
`git diff --check` прошли. Shell entrypoint проверен в локальном Linux без
сети: в обычном режиме выполняет `alembic upgrade head`, с флагом пропускает
его; затем оба варианта запускают API. Флаги **не** ограничивают HTTP-запись
и сами по себе **не** делают БД read-only.

Прежний image `sha256:568d1040...` успешно мигрировал наполненную
live-read копию сервера `0116 → 0176` с сохранением 49 959 старых строк.
Это доказательство **не переносится автоматически** на новый image: миграция
наполненной копии точным кандидатом, парная write-frozen backup/restore,
изоляция всех писателей, systemd/frontend-switch, OIDC-сценарий бухгалтера
и принятие реального месяца остаются открытыми. Решение о выпуске — `NO-GO`.
