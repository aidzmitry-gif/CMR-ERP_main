# Торговые расчёты 60/62: граница пилотного отчёта

Экран «Бухгалтерия → Расчёты 60/62» читает только проведённые строки
бухгалтерской книги выбранного юрлица до конечной даты. Для каждого сочетания
счёта, контрагента, договора и документа расчётов он
показывает начальное сальдо, обороты дебета/кредита за период и конечное
сальдо в BYN. Внутри строки доступны ID проводок и сохранённые на момент
проведения основания. Дополнительные аналитики, например номер банковской
выписки, не разделяют долг одного документа.
Проводки в BYN и валютные позиции одного документа дают одно сальдо в BYN;
их валютная атрибуция перечислена в строке, смешанная атрибуция выделяется
для ручной проверки.

Отчёт сверяет набор ID проведённых строк 60/62, начальное сальдо, дебет,
кредит и конечное сальдо каждого счёта с существующей ОСВ за тот же период.
Пропущенная строка или несовпадение сумм выводятся как ошибка с переходом к
проводке; сводные карточки сумм при этом скрыты. Совпадение означает только
внутреннюю согласованность двух
представлений **одной** ERP-книги; оно не подтверждает данные 1С, первичку или
корректность настройки самих счетов.

Кнопка «Скачать CSV для внутренней сверки» доступна только при совпадении с
ОСВ. CSV содержит **одну строку на документную позицию** (счёт + аналитика):
юрлицо, период, снимки контрагента/договора/документа, валютную атрибуцию,
начало, дебет, кредит и конец в BYN. Колонка `entry_line_ids` перечисляет
точные пары `entry_id:line_id`, а `source_references_json` — источник и его версию в
том же порядке. Поэтому денежные сальдо не дублируются на каждую проводку.
Файл остаётся локальной предварительной расшифровкой ERP, не актом сверки и не
подтверждением соответствия 1С. Текстовые поля экранируются от формул Excel.

В том же экране бухгалтер может скачать пустой шаблон и выбрать отдельный
**нормализованный UTF-8 CSV 1С**. Его обязательные колонки, строго в указанном
порядке: `source_system,organization_id,period_start,period_end,account,category,counterparty,contract,settlement_document,opening_byn,debit_byn,credit_byn,closing_byn`.
`source_system` указывается как `1C`, `organization_id` — ID выбранной книги ERP
после явного сопоставления юрлица, даты совпадают с выбранным периодом. Одна
строка представляет один счёт и документ расчётов; суммы BYN имеют две десятичные
цифры, конечное сальдо равно началу + дебет − кредит. Отсутствующая аналитика,
повтор ключа, отрицательный оборот или чужой период/книга останавливают сравнение.
Сверяются буквальные снимки счёта, категории, контрагента, договора и документа;
одноимённые объекты разных систем требуют отдельного сопоставления устойчивых ID
и проверки бухгалтером. Экран показывает отсутствующие с каждой стороны ключи
и отличающиеся четыре суммы. Файл не передаётся в API: браузер читает его байты,
показывает SHA-256 и результат только для текущей книги и периода. Отпечаток
помогает связать рабочую проверку с внешним пакетом, но сам по себе не доказывает
происхождение файла из 1С или полноту выгрузки. Совпадение — предварительная
проверка, а не акт сверки или разрешение закрыть период.
По кнопке скачивается локальный JSON-черновик: SHA-256 точных байтов выгружаемого
ERP CSV и выбранного файла 1С, книга, период, число строк, расхождения по
документам и суммы с точными `entry_id:line_id`. Он исчезает из экрана после
смены книги, периода или повторной загрузки отчёта. Черновик не подписывается,
не загружается на сервер и сам по себе не доказывает происхождение внешнего
файла, сверку бухгалтером или готовность закрыть месяц.

Банковские поступления/выплаты и зачёты показаны отдельно **как движения**.
Выплата по счёту расчётов не считается автоматически возвратом клиенту:
юридический вид операции должен подтверждаться первичным документом.
Авансы выделяются только при явной аналитике `customer-advance:` или
`supplier-advance:`. Неизвестные либо неполные аналитики не объединяются с
известным долгом и выводятся на проверку. Встречное сальдо без доказанного
авансового документа остаётся неклассифицированным.

Это предварительная управленческая сводка в пределах счетов 60/62. Сроки
оплаты, просрочка, взаимозачёты вне этих счетов, полнота возвратов, сверка
актов и правильность применённых ставок ею не подтверждаются. Статус CRM-счёта,
текущее имя контрагента и записи старого финансового модуля суммы не меняют.
Для бухгалтерской приёмки требуются сверка с ОСВ по аналитике, документами
расчётов и данными 1С за пилотный месяц.
