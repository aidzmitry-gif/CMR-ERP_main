# Пакет входных данных: первый закрытый месяц

Заполняется бухгалтером и операторами перед пилотным закрытием. Пустое, неизвестное или неподтверждённое поле блокирует соответствующий импорт, расчёт или контроль; его нельзя заменить предположением.

Легенда: **[Ввод]** — предоставляет бухгалтер/оператор; **[ERP]** — уже представлен локальным модулем; **[Внешнее]** — доказательство или решение вне ERP.

| Поле | Значение | Статус |
| --- | --- | --- |

| **[Ввод]** Юрлицо: наименование, УНП, устойчивый внешний ID |  |  |
| **[Ввод]** Главный бухгалтер / бухгалтер / оператор банка: ФИО и устойчивый ID учётной записи |  |  |

Данные разных юридических лиц не объединяются.

| **[Ввод]** Устойчивый source ID | Дата | Счёт | Валюта | Дт / Кт | Сумма | Аналитика | Владелец | Первичный источник |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  | контрагент, договор, склад, номенклатура, партия и иное обязательное |  |  |

**[ERP]** Импорт входящих остатков создаёт атомарный пакет с `source_system`, `source_digest`, контрольными итогами и квитанцией. **[Внешнее]** Нужны подписанный/выгруженный источник, правила владельца и акт сверки; без них импорт и сверка блокируются.

## 5. Реестры для сверки

| Реестр | **[Ввод]** Обязательные поля | **[ERP]** Контроль | **[Внешнее]** Блокер |
| --- | --- | --- | --- |
| Банк | source ID, дата, счёт, направление, сумма, валюта, назначение, владелец | импорт/привязка и поиск непроведённых строк | формат выписки, полнота, сверка с 1С |
| Склад | документ ID, склад, SKU, партия, количество, стоимость, владелец | остатки и проводки | инвентаризация и основания стоимости |
| Расчёты | контрагент, договор, документ, срок, валюта, сальдо | аналитика проводок | акт сверки с контрагентом |
| НДС | документ, дата, ставка/режим, сумма, ЭСЧФ и статус доказательства | входной/исходящий регистр | проверка вычета, ЭСЧФ и подтверждающих документов |
| Валюта | операция ID, валюта, дата, сумма, курс, масштаб, источник | audit-квитанция FX | подтверждённый официальный источник |

Банковский пилот поддерживает ручной/CSV BYN-контур, но не подтверждает полноту реальной выписки, валютное проведение или отключение 1С: [BANK-PILOT-STATUS.md](BANK-PILOT-STATUS.md).

## 7. Протокол первого месяца

1. **[Ввод]** Зафиксировать паспорт пилота, политику и манифест; пустые обязательные поля зарегистрировать как блокеры.
2. **[ERP]** Загрузить и подтвердить только проверяемые пакеты, сохранив квитанции и source digest.
3. **[Ввод]** Сверить банк, склад, расчёты, НДС и остатки с первичными источниками; записать расхождения и владельца исправления.
4. **[ERP]** Выполнить контроль закрытия за месяц: очереди непроведённых документов, доступная политика, регистры НДС, ОС, производство, зарплата, ВЭД и связанные квитанции.
5. **[Внешнее]** Главный бухгалтер подтверждает результаты сверки и решение по каждому блокеру; без этого месяц не считается закрытым.
