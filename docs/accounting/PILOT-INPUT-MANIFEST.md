# Машиночитаемый манифест пилота бухгалтерии

Перед импортом начальных остатков бухгалтер собирает отдельную папку с исходными
файлами и `manifest.json`. Проверка выполняется локально:

```powershell
py -3 scripts/accounting_pilot_preflight.py --manifest <путь-к-manifest.json>
```

Команда не подключается к 1С, не записывает данные в ERP, не создаёт квитанции и
не ставит документы в очередь. Успешный результат подтверждает только полноту,
целостность и внутреннюю совместимость входного пакета. Проведение импорта и
принятие сверки остаются отдельными действиями бухгалтера.

## Состав папки

Пути в манифесте относительны к его папке. Нельзя указывать абсолютные пути,
`..`, повторять путь или пару `source_system`/`source_id`. Для каждого файла
укажите SHA-256 в нижнем регистре и основание его происхождения. Для `opening_balances`,
`osv_left` и `osv_right` допустим ровно один файл; остальные виды могут состоять
из нескольких файлов.

Обязательные виды: `opening_balances`, `bank_statement`, `inventory`,
`receivables`, `vat`, `fx`, `primary_documents`, `osv_left`, `osv_right`.
Дополнительно можно приложить `supporting_calculation`: он сохраняет контекст
расчёта, но не закрывает ни один обязательный вид доказательства.

Каждый файл получает два явных признака происхождения:

- `evidence_role=required_evidence` — доказательство, которое закрывает один
  обязательный вид;
- `evidence_role=supporting_calculation` — вспомогательный расчёт, например
  таблица распределения доставки. Такой файл допускается только с
  `kind=supporting_calculation`.

Поле `source_class` не позволяет выдать оперативную таблицу за первичный
документ. Для выписки банка нужна `bank_statement`, для курсов —
`official_rate`, для первички — `primary_document`; реестры и ОСВ принимают
только соответствующий экспорт или регистр. Оперативный файл можно указать
только как `operational_workbook` во вспомогательном расчёте.

`opening_balances` — JSON пакета `opening-balance-v1`, который уже проходит
модель ERP. Его `source_system` и `cutover_date` должны совпасть с манифестом.
`osv_left` и `osv_right` — нормализованные CSV ОСВ из ERP: одна организация,
один период, статус `closed_periods`, ноль непроведённых документов и ноль
расхождений. Программа сверяет их хэши и данные, но не сохраняет файлы.

## Строгая схема `belarus-pilot-input-v2`

Замените все значения в угловых скобках подтверждёнными данными. Пустые поля,
`unknown`, `n/a`, `todo` и другие заполнители отклоняются. Политика должна
действовать в дату перехода, а дата перехода — быть первым днём пилотного месяца.

```json
{
  "protocol_version": "belarus-pilot-input-v2",
  "pilot": {
    "month": "<YYYY-MM>",
    "cutover_date": "<YYYY-MM-01>",
    "authorization_evidence": "<решение о пилоте или ссылка на протокол>"
  },
  "organization": {
    "external_id": "<устойчивый ID юрлица в источнике>",
    "name": "<полное наименование юрлица>",
    "unp": "<9 цифр УНП>"
  },
  "owners": {
    "chief_accountant": "<устойчивый ID главного бухгалтера>",
    "accountant": "<устойчивый ID бухгалтера>",
    "bank_operator": "<устойчивый ID оператора банка>"
  },
  "policy": {
    "effective_from": "<YYYY-MM-DD>",
    "effective_to": "<YYYY-MM-DD>",
    "revision": "<редакция учётной политики>",
    "order_reference": "<приказ или иной документ>",
    "responsible_id": "<устойчивый ID ответственного>",
    "evidence": "<ссылка или идентификатор подтверждённой политики>"
  },
  "artifacts": [
    {
      "kind": "<один из обязательных видов>",
      "evidence_role": "<required_evidence или supporting_calculation>",
      "source_class": "<класс происхождения файла>",
      "source_system": "<система-источник>",
      "source_id": "<устойчивый ID выгрузки или документа>",
      "path": "<относительный путь к файлу>",
      "sha256": "<64 символа SHA-256 файла в нижнем регистре>",
      "evidence": "<основание происхождения файла>"
    }
  ]
}
```

Сначала заполняется манифест, затем для каждого файла рассчитывается его хэш.
После любого изменения файла нужно сформировать новый SHA-256 и повторить
проверку. Успешный preflight не назначает данные основной компании, не снимает
внешние блокеры и не заменяет согласование реального перехода.
