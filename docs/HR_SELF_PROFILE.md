# Личная HR-карточка

Приглашённый сотрудник заполняет анкету на `/onboarding`. После активации она доступна по нажатию на аватар/имя в меню и по `/profile`.

Необязательные сведения: дата рождения, телефон, город, образование/специальность, даты рождения детей. Количество детей и возраст рассчитываются из списка; имена детей не собираются. «Не указывать» хранится отдельно от «Нет детей». Любое личное поле можно очистить.

«Сохранить черновик» позволяет продолжить позже. «Я заполнил карточку» сохраняет статус submitted, даже если сотрудник предпочёл не раскрывать необязательные сведения. Это не проверка HR и не активация доступа. ФИО, должность, отдел, учётная запись и роль не изменяются через анкету.

HR открывает «Карточки сотрудников» на странице HR или `/erp/hr/employees`. Список возвращает только рабочие сведения и статус анкеты. Частные поля читаются отдельно: самим сотрудником либо пользователем с действующей ролью `hr`. Роли director/commercial/admin сами по себе этого доступа не дают. HR просматривает анкету, но не заполняет её от имени сотрудника.

## Граница доступа

- `GET/PUT /hr/me/profile`: запись определяется по проверенному Keycloak subject и локальной связи app_user.employee_id; клиент не передаёт ID владельца.
- Единственное исключение из запрета HR для onboarding/CRM — точный путь `/hr/me/profile`, методы GET/PUT. Все остальные ограничения сохраняются.
- Отозванная/заблокированная учётная запись и неактивная HR-карточка доступа не имеют.
- `GET /hr/employee-profiles/{id}`: только HR; чтение фиксируется в аудите без значений личных полей.
- Изменения фиксируют только статус и ревизию. Персональные значения не попадают в аудит или outbox. Ответы профиля имеют Cache-Control: no-store.
- Ревизия и блокировка родительской записи защищают от перезаписи из устаревшей вкладки; клиент получает 409 и предложение обновить страницу.

## Развёртывание

Миграция 0112 согласована оператором. Добавляет отдельную таблицу `hr.employee_profile`, не изменяет существующие EmployeeOut личными данными и не заполняет анкеты автоматически. До запуска backend с обновлённым gitlink HR требуется применить 0112. Затем разворачивается frontend из того же ERP-коммита. Код обратного хода миграции удаляет анкеты: при откате приложения таблицу следует сохранять.

HR-ветка основана на текущем gitlink ERP e4be466. В нём уже присутствует payroll summary d4d96e0 и документация e4be466, отсутствующие в main HR-репозитория на момент подготовки. Они сохранены, чтобы не регрессировать текущее приложение.

При приглашении логин целиком кириллицей преобразуется в вариант из email; этот вариант возвращается preflight для явного подтверждения до отправки письма.
