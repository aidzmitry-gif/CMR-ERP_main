# Телефония ERP: click-to-call

## Что проверяет локальный контракт

`POST /integrations/telephony/originate` сохраняет существующее право
`integrations.telephony`. До обращения к провайдеру локально проверяются два
входных параметра:

- `vnut` — точная строка из 1–3 ASCII-цифр; значение не очищается и не
  обрезается, поэтому ведущие нули сохраняются;
- `number` — номер, который проходит существующую нормализацию
  `normalize_e164`; значение без цифр отклоняется.

URL исходящего шлюза считается настроенным только при наличии абсолютного
`http://` или `https://` URL с host. Пустой, относительный, не-HTTP(S) или
явно malformed URL даёт `503` до создания HTTP-клиента. Ошибка входных данных
даёт `422`. Ошибка провайдера даёт стабильный `502` без текста исключения,
URL, query-параметров или credentials в ответе.

Локальные mock-тесты проверяют успешный `POST` с query-параметрами,
сохранение ведущих нулей, отсутствие HTTP при плохом `vnut` или номере,
отсутствие HTTP при плохой конфигурации, сохранение permission-гейта и
санитизацию ошибки провайдера. Реальный сетевой вызов в тестах не выполняется.

## Что пока не подтверждено

Для подключения к production нужен фактический URL `client_call_gen.php` от
провайдера; в репозитории его нет. Также не подтверждены mapping внутреннего
номера к сотруднику, контракт записи разговоров и UTM-меток. UI click-to-call
остаётся отдельной незавершённой частью. Поэтому локальные проверки не дают
оснований считать телефонию подключённой или полностью готовой в production.
