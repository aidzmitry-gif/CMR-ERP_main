Как AI работает со справочниками

Структурный доступ (SQL/MCP) для точности и историчности; эмбеддинги — только нечёткий поиск.

AI берёт точные значения структурно поверх semantic-слоя · историчность учитывается (на дату) · pgvector — только «похоже на…», не для точных полей.

Цепочка ответа

От вопроса пользователя до точного значения с учётом истории.

1
Вопрос пользователя
«Какой НДС действовал у отгрузки ООО «Ромашка» 15 мая и какой у неё УНП?»
2
Вызов инструментов
MCP-tool call
{ "tool": "reference.query", "ref": "vat_rates", "as_of": "2026-05-15" }
{ "tool": "reference.query", "ref": "counterparties", "match": { "title": "Ромашка" } }
3
Структурный запрос
Сгенерированный SQL
SELECT rate FROM public.ref_vat_rate
WHERE code='НДС'
  AND start_date <= DATE '2026-05-15'
  AND (end_date IS NULL OR end_date > DATE '2026-05-15');
SELECT unp FROM public.counterparty
WHERE title ILIKE '%Ромашка%' AND is_active;
4
Результат
УНП 191234567 НДС на 15.05.2026 = 25% историческая ставка текущая 20%

★ Точно, с учётом истории — значение взято из эталонной записи на дату отгрузки, а не текущее.

Semantic / metrics-слой
точка входа AI

AI ходит сюда за определениями сущностей и метрик, не в сырую схему.

Контрагент

Эталонная карточка (golden record) по natural key УНП + код ERP; алиасы и id 1С склеены.

Отгрузка

Расходный документ движения товара контрагенту с датой проводки.

Действующая ставка

Значение SCD2 на дату: start_date ≤ дата < end_date (текущая — «по» пусто).

Активная запись

Не в архиве (is_active); удаления нет — только 🗃 архив с аудитом.

pgvector — вторично
не для точных значений

Только нечёткий поиск названий и дедуп похожих записей.

Где помогает

«Ромашка» ↔ «ООО Ромашка» ↔ «Romashka» — поиск похожих и склейка дублей в golden record.

Границы

При фильтрации (на дату, по статусу) recall падает — вектора не дают точных значений полей.

Масштаб

Выделенная vector DB — только при высоком QPS/большом объёме; иначе pgvector в PostgreSQL 16.

Почему так

Структурный доступ (SQL/MCP поверх semantic-слоя) даёт точность и историчность — значения берутся на дату из эталонных записей. Вектора — лишь «похоже на…» для поиска и дедупа. Граф знаний (KG) для этого не обязателен.
