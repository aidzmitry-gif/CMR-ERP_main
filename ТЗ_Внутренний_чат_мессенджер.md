**Тип:** новый **общий модуль `messaging`** (кросс-компанийный, используют все отделы)
**Схема БД:** `messaging` · **API-префикс:** `/messaging` · **Источник схемы Postgres:** Alembic
**Постановка:** product owner (ООО «Аккумуляторные решения») · **Дата:** 2026-06-13

**Связь:** правая панель чатов в CRM — [chats-panel.tsx](frontend/src/components/chats-panel.tsx) (SALES-49); окно звонка — [ТЗ_Окно_звонка_и_резерв.md](ТЗ_Окно_звонка_и_резерв.md).

## 0. Зачем отдельный модуль (а не в sales/office)

Внутренний чат нужен **всем 9 модулям** (продажи, производство, склад, закупки, HR…). Если положить его в `sales` или `office` — получим неверную связанность (один отдел владеет общей инфраструктурой). Поэтому:

- **Данные и API внутреннего чата** — новый общий модуль `messaging` (как `knowledge`/`office`), по образцу эталона `sales`.
- **Внешние диалоги с клиентами** остаются там, где есть — омниканал по сделке (`sales.Message`, `/sales/chats`). Их **не переносим**, а показываем рядом во вкладке.
- **Правая панель** в канбане — общий фронт-компонент, агрегирует оба потока (Коллеги | Клиенты).

> **Граница (важно):** бэкенд `messaging` — НЕ полоса sales. Моя зона (sales/CRM) — только клиентская вкладка панели (`/sales/chats`, уже готова) и монтаж общего виджета. Реализацию модуля `messaging` ведёт отдельная/офисная сессия — координация через `coordination/`.

## 1. Две поверхности (как и где показываем)

### 1.1. Выезжающая рейка в канбане каждого отдела (быстрый доступ)
Переиспользуем паттерн `chats-panel.tsx` (свёрнутая рейка ~68px → оверлей ~300px по наведению). **В свёрнутом виде видны аватары ОБЕИХ групп одним столбиком** (коллеги + клиенты) — не прячем клиентов за переключателем:

- **Коллеги** — внутренние диалоги (личка + каналы): аватар/инициалы + красный бейдж непрочитанных.
- **Клиенты** — внешние диалоги по сделкам (текущий `/sales/chats`); аватар с **бирюзовым кольцом**-маркером, тоже виден свёрнутым.
- Между группами — тонкий разделитель; **подписи секций «Коллеги»/«Клиенты»** и имена/последние сообщения проявляются только при раскрытии (оверлей).

Бейдж непрочитанных — суммарно на свёрнутой рейке (видно всегда) + по каждому диалогу. В других отделах раздел «Клиенты» = их собственные внешние диалоги (или скрыт, если у отдела их нет).

### 1.2. Глобальный хаб «Чаты» (полноценный мессенджер)
Отдельный пункт верхней навигации → полноэкранная страница (как Slack/Teams):
- слева список: каналы (по отделам/темам) + личные диалоги, поиск;
- центр: лента сообщений, треды/ответы, вложения, упоминания `@`;
- глобальный бейдж непрочитанного в навигации.

Рейка — «глянуть и быстро ответить»; хаб — «работать в переписке». Один источник данных, две поверхности.

## 2. Гранулярность — и личка, и группы (одна модель)

Унифицированная `Conversation` с полем `kind`:

| kind | Что | Участники |
|------|-----|-----------|
| `dm` | Личка 1:1 с коллегой | ровно 2 пользователя |
| `channel` | Групповой чат: отдел / тема / проект | N пользователей, есть название |
| `deal` *(фаза 2)* | Командный чат, привязанный к сделке/клиенту | команда по сделке; мост к CRM-контексту |

Внешние клиентские диалоги (`sales.Message`) — отдельная сущность, **показываются во вкладке «Клиенты»**, не сливаются в `Conversation` (разные каналы, права, омниканал).

## 3. Модель данных (схема `messaging`)

```
conversation
  id            PK
  kind          str(16)        # dm | channel | deal
  title         str(255)|null  # для channel; для dm — вычисляется из участников
  department    str(32)|null   # привязка канала к отделу (опц.)
  deal_id       int|null       # для kind=deal (мягкая ссылка sales.deal)
  created_by    int            # app_user.id
  created_at    datetime

conversation_member
  id              PK
  conversation_id FK
  user_id         int          # мягкая ссылка app_user / hr.employee
  role            str(16)       # member | admin
  last_read_at    datetime|null # отметка прочтения → из неё считаем непрочитанные
  muted           bool
  UNIQUE(conversation_id, user_id)

chat_message
  id              PK
  conversation_id FK
  author_id       int
  text            text
  attachments     json|null     # [{name,url,size}]
  reply_to        int|null      # тред/ответ
  mentions        json|null     # [user_id] для @упоминаний
  created_at      datetime
  edited_at       datetime|null
```
- **Непрочитанные** = `chat_message.created_at > member.last_read_at` (по конкретному участнику). Бейдж — сумма по всем его диалогам.
- Мягкие ссылки на `app_user`/`hr.employee`/`sales.deal` — без cross-schema FK (как везде в проекте).

## 4. API (`/messaging`)

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/messaging/conversations` | список диалогов текущего пользователя (+ unread) |
| `POST` | `/messaging/conversations` | создать dm/channel (участники, тип) |
| `GET` | `/messaging/conversations/{id}/messages` | история сообщений |
| `POST` | `/messaging/conversations/{id}/messages` | отправить сообщение |
| `POST` | `/messaging/conversations/{id}/read` | отметить прочитанным (обновить `last_read_at`) |
| `GET` | `/messaging/stream` | SSE-поток новых сообщений/упоминаний (как окно звонка) |
| `GET` | `/messaging/unread` | суммарный счётчик для бейджа навигации |

## 5. События

- `messaging.message.sent` (→ audit, доставка подписчикам через SSE).
- `messaging.mention` (упоминание `@user`) → уведомление пользователю.
- (фаза 2) `messaging.deal_chat.opened` — связка командного чата со сделкой.

Realtime — SSE in-process (как в окне звонка), при масштабировании → Redis pub/sub (заложить).

## 6. Права и приватность

- Видеть диалог может только его участник (`conversation_member`).
- Каналы: открытые (отдел может вступить) vs закрытые (по приглашению) — поле на `conversation` (фаза 2).
- Внешние клиентские диалоги — права sales (как сейчас).

## 7. Связь с правой панелью (что делаю я в полосе sales)

1. Расширить `chats-panel.tsx`: добавить вкладки **Коллеги | Клиенты** (Клиенты = текущий рендер; Коллеги = новый источник `/messaging/conversations`).
2. Бейдж непрочитанных на рейке = сумма (клиенты `unread` + коллеги `unread`).
3. Общий виджет рейки — переиспользуемый во всех отделах (выносим из CRM-специфики в общий компонент).

**Вне моей полосы (координация):** весь модуль `messaging` (модели/миграции/API/SSE), глобальный хаб «Чаты», навигация. Это отдельная/офисная сессия.

## 8. Порядок (предложение)

1. Модуль `messaging`: модели + миграция → API диалогов/сообщений/read → SSE → события. *(чужая полоса)*
2. Глобальный хаб «Чаты» (страница-мессенджер). *(чужая полоса)*
3. Рейка: вкладки Коллеги|Клиенты + суммарный бейдж + вынос в общий компонент. *(частично моя полоса — клиентская вкладка)*
4. Фаза 2: `deal`-чаты (командный чат по сделке) — мост sales↔messaging; открытые/закрытые каналы; вложения/треды.
