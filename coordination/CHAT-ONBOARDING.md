# Как мы работаем — онбординг для ЛЮБОГО чата флота

> Вставь это (или ссылку на файл) первым сообщением в каждый рабочий чат. Создано 2026-06-27.
> Полнее: `coordination/ACTIVE-SESSIONS.md` (Правила), `coordination/DEPENDENCY-MAP.md`,
> `coordination/COORDINATOR.md` (роль координатора).

Несколько Claude-чатов работают **параллельно** над одним проектом в **ОДНОМ git-worktree**, на
общей ветке `sales-2.0-redesign`. 9 бизнес-модулей — **git-submodules**. Поэтому дисциплина обязательна.

## В начале работы (обязательно)

1. Прочитай `coordination/ACTIVE-SESSIONS.md` (кто что держит · хотспоты · счётчик миграций ·
   «недавно влито») и хвост `coordination/.activity.local.md` (что напушил флот).
2. Назови свою **ПОЛОСУ** (зона + конкретные пути) и впиши строку в «Полосы». Работай только в ней.

## Жёсткие правила

- **Не лезь в чужие пути.** Совпали — пингуй оператора/координатора, не правь вслепую.
- **Хотспот-файлы** (`config/settings.py`, `config/modules.py`, `core/services/__init__.py`,
  `core/db/base.py`, `core/domain/models.py`, `frontend/src/lib/api.ts`, `.claude/settings.json`) —
  захватывай в «Хотспоты» на время правки, освобождай после коммита; один держатель за раз.
- **Shared-kernel** (`core/domain/models.py`: Counterparty/Sku/User/...) — меняешь только по
  согласованию: ломает ВСЕ модули.
- **Миграции** — линейная цепочка. Перед взятием: `grep -h down_revision migrations/versions/*.py`
  → найди head (ревизия, на которую никто не ссылается) → возьми next → **СРАЗУ впиши в счётчик**.
  НЕ нумеруй вперёд незакрытых дыр (сломает `alembic upgrade head` на деплое).
- **Мастер-данные** (контрагент/номенклатура) пишутся ТОЛЬКО через MDM-сервис ядра
  (`core.services.reference_import`/`mdm`), не `session.add(Counterparty/Sku)` напрямую. Остатки —
  ОПЕРАЦИОННЫЕ данные, через `core.services.stock`, НЕ в справочники. См. `mdm-data-class-seam.md`.
- **Коммит** — только СВОИ файлы явным `git add <файлы>` (НЕ `git add .` — в дереве чужой WIP).
- **Push** (только по явной просьбе пользователя) — только СВОЙ коммит **cherry-pick'ом на чистый
  origin-tip** через временный worktree, не утаскивая чужие незапушенные коммиты.
- **НИКОГДА `amend`/`reset`/`rebase` на общей ветке** — HEAD дрейфует под флотом, затрёшь чужой
  коммит (git-хук `prepare-commit-msg` это блокирует). Лучше — своя ветка/worktree на сессию:
  `git worktree add ../_wt_<полоса> -b <полоса>`.
- **Submodule** — правка = коммит в репозиторий модуля + bump указателя в суперпроекте; bump только
  своей сессией, не bump чужой модуль.
- **Приоритет при конфликте целей** (PLATFORM.md): 1) деньги собственнику → 2) безопасность →
  3) функциональность → 4) эстетика. Меньший номер побеждает.

## Что уже автоматизировано (не держи в голове)

- **Git-хуки** (`.githooks/`) на commit/push сами пишут `coordination/.activity.local.md` + флажат
  хотспоты/миграции/новые события шины; pre-commit **БЛОКИРУЕТ** amend на общей ветке.
- **Quality-хук** гоняет ruff (PostToolUse) и ruff/tsc (Stop) на твоих правках.

## Координация

- Есть **координационный чат** — владелец реестра (`ACTIVE-SESSIONS`/`DEPENDENCY-MAP`/счётчик
  миграций) + hook-инфры + арбитража. За **cross-lane решениями** (тронуть хотспот/shared-kernel,
  взять миграцию, мержить, открыть новый чат) — к нему, не решай в одиночку.
- Свою фичеполосу коммить/пушь **свободно** — координатор не бутылочное горлышко.
