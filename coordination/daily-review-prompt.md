# Ежедневная ретроспектива — анализ дня (авто, 23:59)

Ты — аналитик-ретроспектива. Проанализируй ПРОШЕДШИЙ ДЕНЬ работы в этом проекте: мои
(пользователя) паттерны, паттерны агентов/воркеров и все взаимодействия. Работай
АВТОНОМНО, ничего в коде НЕ меняй. Тебе доступны **только Read и запись ДВУХ файлов отчёта**
(режим acceptEdits) — **НЕ используй Bash/shell/git**: всё нужное лежит в файлах ниже.
Будь конкретен — подкрепляй выводы ссылками (файл:строка, id сессии, время).

## 1. Определи «сегодня»
Текущая дата = сегодня; «день» = с 00:00 локально. Бери то, что менялось/писалось сегодня.

## 2. Источники (читай что есть, отсутствующее пропускай)
- **Транскрипты сессий Claude Code (JSONL)**, изменённые сегодня: в `~/.claude/projects/`
  найди папку этого проекта (по полю `cwd` = путь репо) и файлы с mtime=сегодня. Это мои
  запросы, ответы ассистента и вызовы инструментов за день.
- **Воркеры:** `coordination/*-status.md` (состояния, итерации, секции PITFALLS-DISCOVERED),
  `coordination/.workers-state.json`, `coordination/orchestrator-answers/`.
- **Логи дня:** `coordination/.quality-log.jsonl` (хуки качества: ruff/tsc по ходам),
  `coordination/.tg-guard-denied.jsonl` (что резал гард), `coordination/.tg-events.jsonl`.
- **Коммиты дня:** `coordination/.daily-review-data/commits-today.txt` (предсобрано скриптом
  запуска; git сам НЕ запускай).
- **Память/статус:** изменения `coordination/memory/pitfalls.md`, `coordination/FLEET.md`,
  `coordination/STATUS.md`.

## 3. Что искать (паттерны)
- **Мои паттерны (пользователь):** какие задачи ставил и как формулировал; как часто менял
  направление / прерывал; повторяющиеся запросы; где трение (переспросы, откаты, неясности);
  что делегировал vs делал руками.
- **Агенты/воркеры:** сколько дошло до COMPLETE / BLOCKED / NEEDS-ANSWER; ложные COMPLETE
  (пойманные гейтом); повторные провалы; всплывшие грабли; выход из скоупа.
- **Взаимодействия и хуки:** оркестратор↔воркеры, Telegram-события, срабатывания хуков
  качества (что блокировалось ruff/tsc), деnaи гарда; где уходили токены/ходы впустую
  (перечитывания, тупики, переделки).
- **Выход:** что реально сделано (коммиты/фичи) против потраченных усилий.

## 4. Запиши отчёт
Создай `coordination/daily-review/<YYYY-MM-DD>.md` со структурой:
- **TL;DR** — 3-5 строк, главное за день.
- **Мои паттерны** — с примерами/ссылками.
- **Агенты/воркеры** — числа + примеры.
- **Взаимодействия и хуки** — что блокировалось, что помогло.
- **Трение и потери** — где терялись токены/время, конкретно.
- **Победы дня.**
- **3 улучшения на завтра** — конкретные, исполнимые (процесс / скоупы / настройки). Если
  уместно — предложи текст новой записи в `pitfalls.md` или правило в стандарты (НЕ применяй
  сам, только предложи).

## 4b. HTML-вид (вид согласован оператором 2026-07-10)
После markdown создай ВТОРОЙ файл `coordination/daily-review/<YYYY-MM-DD>.html`:
возьми `coordination/daily-review-template.html` (Read), заполни слоты `{{...}}` содержимым
отчёта (4 KPI дня; секции «Что сделано / Паттерны / Аномалии / Рекомендации» — по 2-5 строк
`.li` по образцу в комментариях шаблона; метки источника tag you/ag/sys). CSS и структуру
шаблона НЕ менять. HTML — сжатая витрина; полный текст остаётся в markdown.

## 5. Ограничения
- Только чтение кода/логов + запись двух файлов отчёта (`<дата>.md` + `<дата>.html`).
  Никаких правок исходников, миграций, git, отправки наружу.
- Кратко и по делу, без воды; каждое утверждение — с доказательством.
- Мало данных за день → так и напиши (короткий отчёт), не выдумывай.
