# ТЗ CURSOR: запуск лидов и продаж на ERP-сервере

**Дата:** 2026-07-21  
**Владелец серверных действий:** CURSOR  
**Владелец кода и GitHub:** Codex  
**Приоритет:** P0 — запуск пилота отдела продаж.

## Цель

Подготовить ERP к работе пилотной группы продаж: сотрудник входит под своей учётной записью,
ведёт лид до сделки, формирует счёт и видит тестовую оплату. После сдачи CURSOR передаёт
доказательства; серверные секреты не передаёт.

## Релиз

Выкатить `origin/main` не ниже commit:

```text
13672d1e6a866da1fc168ae8170893d9f0e16c17
```

В состав входят:

- PR #4 (`CRM`) — входящий звонок привязывается только к открытой сделке;
- PR #19 — лента звонков на карточке сделки;
- PR #20 — запусковые тесты CRM и server-handoff.

## Границы ответственности

CURSOR делает только серверные/операционные действия: Git pull, субмодули, контейнеры,
миграции, Keycloak/OIDC, загрузка данных, 1С и каналы лидов, smoke.

CURSOR **не** редактирует production-код на сервере, не создаёт ручные непушенные фиксы и не
изменяет GitHub-ветки. При ошибке фиксирует команду, HTTP-статус и релевантный лог, затем передаёт
Codex.

## 1. Точка отката и выкладка

1. До изменений зафиксировать на сервере:
   - `git rev-parse HEAD`;
   - `git submodule status`;
   - `docker compose ps`;
   - текущую версию Alembic.
2. Убедиться, что серверное рабочее дерево чистое. Грязное дерево не перетирать.
3. Обновить суперпроект и субмодули до опубликованного `origin/main`, собрать и поднять стек.
4. Подтвердить:
   - все необходимые контейнеры `Up`;
   - `/health` отвечает 200;
   - `alembic heads` возвращает **ровно одну** голову;
   - нет traceback / migration failure в последних логах app.

При красном смоуке не делать destructive rollback БД вслепую: прислать результаты Codex.

## 2. Учётные записи и доступ

В Keycloak создать либо подтвердить реальные учётные записи:

| Тип | Минимальная роль | Проверка |
|---|---|---|
| РОП | `sales_head` | видит воронку и управленческие экраны продаж |
| Продавец | `sales` | создаёт/ведёт разрешённые лиды и сделки |
| Негативный тест | без sales-роли | не получает доступ к данным продаж |

Требования:

- пароль сотрудника не временный либо выдан сотруднику безопасным способом;
- вход идёт через рабочий OIDC-поток, не через заголовок роли;
- по каждой роли проверить `/crm/leads` и `/crm/deals`;
- указать в отчёте только логин/роль/результат, **без паролей и токенов**.

## 3. Стартовые данные

Загрузить либо проверить наличие минимального рабочего набора:

- контрагенты и контакты с телефонами;
- номенклатура/услуги, цены и доступные единицы измерения;
- 3–5 активных сделок и 3–5 активных лидов;
- назначенные владельцы (реальные продавцы);
- стадии воронки, причина отказа и срок первого ответа.

Если сведения получаются из 1С, не заменять их демо-данными. Если живой фид ещё не готов,
загрузить явный пилотный набор и отметить это в отчёте.

## 4. Обязательный сквозной smoke

Под учётной записью продавца пройти и зафиксировать результат каждого шага:

1. Создать лид вручную.
2. Заполнить контакт, источник, ответственного, результат квалификации и следующий шаг.
3. Конвертировать лид в сделку; проверить сохранение связи с лидом.
4. Добавить товар/услугу, цену и количество.
5. Сформировать КП и счёт.
6. Зарегистрировать **тестовую** оплату штатным интеграционным/финансовым путём.
7. Убедиться, что офисный документ этой сделки стал «Оплачено».
8. Проверить, что сделка и созданный документ видны РОПу.
9. Войти пользователем без sales-роли: убедиться, что данные продаж недоступны.

Дополнительно, если Zruchna уже подключена: принять один тестовый входящий звонок от номера
контакта с открытой сделкой и подтвердить появление звонка в ленте этой сделки. Не подключена —
пометить «отложено», это не блокирует ручной пилот.

## 5. Формат отчёта CURSOR

Вернуть одним сообщением:

```text
Релиз: <server HEAD>, origin/main=<SHA>, sales=<gitlink SHA>, leads=<gitlink SHA>
Контейнеры: <Up/ошибка>
Health: <HTTP status>
Alembic heads: <ровно один SHA / ошибка>
OIDC: РОП <логин, результат>; продавец <логин, результат>; negative <результат>
Данные: <что загружено, источник>
Smoke: L1 ... L9 — PASS/FAIL и краткое доказательство
АТС: PASS / отложено / FAIL
Ошибки: <команда, HTTP status, фрагмент лога без секретов>
```

## Критерий сдачи

Сдано, только когда L1–L9 прошли, все сервисы здоровы, доступы реальны и единственная миграционная
голова подтверждена. При любом FAIL не маскировать проблему демо-данными или server-side hotfix:
передать доказательства Codex для исправления в репозитории.
