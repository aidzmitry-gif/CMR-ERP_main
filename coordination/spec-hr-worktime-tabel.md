# Спец: Учёт рабочего времени + Табель (HR) — от оператора 2026-07-02

> Источник: оператор + файл `D:/6 Проекты/CRM ERP/Табель работчего времени июнь2026.xlsx`
> (T-13, июнь 2026, 20 сотрудников, исполнитель Жуковская О.Н.). Домен — модуль **hr** (HR-10).
> **Метод: HTML-first** (мокап → Gate 1 оператор → Gate 2 фичасибилити → реализация слайсами).
> Пока — СПЕКА + мокап; бэкенд/схему НЕ строим до Gate 1/2.

## Что просил оператор (дословно)
1. Учёт начала/конца рабочего дня — **кнопки** (нажал → пошёл счётчик). Работает «автоматически»
   (просто считается, сколько сотрудник был онлайн на платформе), но кнопка обязательна.
2. Если не нажал — **напоминание** сотруднику, что нужно нажать.
3. Возможность **посмотреть, кто работает, а кто офлайн**, и **сколько** отработал (живой счётчик).
4. **Заполнение табеля** по нажатой кнопке: учитывается, сколько **полных часов** проработал сотрудник
   **согласно контракту (норма)**. Если проработал **больше** — **уведомление руководителю о согласовании**
   добавления доп. часов (переработки) в табель.

## Структура табеля (из xlsx — заземление)
- Матрица: строки = сотрудники (`Таб. номер` `00001`…, ФИО, должность), столбцы E..AH = дни месяца 1..30/31.
- Ячейка дня = **часы** (`8/9/10`…) ИЛИ **код**: `В` — выходной. (Расширим кодами T-13: `О`-отпуск,
  `Б`-больничный, `К`-командировка, `А`-за свой счёт — они уже сведены в итоговых столбцах.)
- Итоговые столбцы: `Рабочее время` (отработано дней), `Часы` (сумма), `Командировка/Больничный/Отпуск/
  За свой счёт` (дни). Идентичность сотрудников — `config/access.py::USERS` (те же 20 человек + роли).

## Модель данных (черновик, hr-схема — уточнить на Gate 2)
- **`hr.work_session`** (присутствие): `employee_key` (таб.номер/username из USERS), `clock_in` (ts),
  `clock_out` (ts, null=открыта), `source` (`button`|`auto`), `date`. Онлайн-длительность открытой = now−clock_in.
  Автосчёт «онлайн на платформе» — фоновый heartbeat (последняя активность) как страховка к кнопке.
- **`hr.work_norm`** (норма по контракту): `employee_key`, `daily_hours` (деф. 8), `week_hours` (40),
  расписание/выходные. Источник — контракт сотрудника (hr; пока — конфиг/справочник).
- **`hr.timesheet_cell`** (табель, месяц×сотрудник×день): `period` (YYYY-MM), `employee_key`, `day`,
  `hours` (Decimal), `code` (nullable: В/О/Б/К/А), `overtime_pending` (bool), `approved_extra` (Decimal).
  Автозаполнение: `hours = min(worked_from_sessions, norm)`; `worked > norm` → `overtime_pending=True`,
  создаётся согласование.

## Три потока (что строим)
### Поток 1 — Кнопка «Начать/Завершить день» + счётчик
- UI: одна кнопка-тумблер в шапке/дашборде сотрудника («Начать рабочий день» → идёт таймер → «Завершить»).
- Открывает/закрывает `work_session`. Живой счётчик = длительность открытой сессии (+ авто-heartbeat как подстраховка).
- **Напоминания:** не нажал «начать» к T1 (напр. начало смены+15м) → пуш; открытая сессия к концу дня без
  «завершить» → пуш. Реализация — фоновый цикл (как `event_bus._background_loop`/approvals.escalate_once) +
  уведомление (Telegram-мост/нотификация). Никакой слежки сверх факта онлайн — по конституции (прозрачно сотруднику).

### Поток 2 — Доска присутствия «Кто онлайн»
- Экран/виджет: список сотрудников с бейджем **онлайн/офлайн** + **отработано сегодня** (живой счётчик у онлайн).
- Группировка по отделу/роли (из USERS/ACCESS_MATRIX). Только чтение; руководителю — по своему отделу, директору — все.
- Реализуемо как `core.register_widget` + страница `/erp/hr/presence`.

### Поток 3 — Табель + согласование переработок
- Экран табеля (грид как xlsx): период-переключатель, строки-сотрудники, дни, коды, итоги. Автозаполнение из сессий.
- Правило: `hours_day = min(worked, norm)`. Если `worked > norm` → ячейка помечается, создаётся **Approval**
  (`core.services.approvals.request`, human-in-the-loop) на руководителя (РОП/директор по ACCESS_MATRIX).
  На **approve** — `approved_extra` добавляется в ячейку и в итог `Часы`; на reject — остаётся норма.
- Коды невыходов (О/Б/К/А) проставляются из HR-событий (отпуск/больничный/командировка) — отдельные потоки HR,
  в этой фиче — поддержать отображение + ручную простановку исполнителем табеля (роль как Жуковская О.Н.).
- Экспорт в xlsx по форме T-13 (совместимо с присланным файлом) — на потом (после Gate 1).

## Платформенные примитивы (переиспользуем — лестница лени)
- Идентичность: `config/access.py::USERS` (20 сотрудников, роли). НЕ заводить второй справочник людей.
- Согласование переработок: **core approvals** (`ApprovalService.request/decide` + эскалация) — не свой флоу.
- Напоминания/фон: паттерн `_background_loop` ядра (поллинг) + Telegram-мост (уже есть) / нотификация.
- Доска: `core.register_widget` + FunnelBoard/бespoke страница. Деньги/часы — Decimal→str на границе.
- Событие шины: `hr.workday.started` / `hr.workday.ended` / `hr.overtime.requested` / `hr.timesheet.updated`.

## Gate 1 (что показать оператору для одобрения)
Кликабельный HTML-мокап: (а) кнопка старт/стоп + счётчик, (б) доска «кто онлайн», (в) грид табеля с
подсветкой переработки и кнопкой «согласовать доп.часы» + попап согласования. Все окна и связи, 2 темы.

## Открытые вопросы к оператору (Gate 1)
1. Норма часов — единая 8ч/40ч или у каждого своя из контракта? Есть ли сменный график/полставки?
2. Кто «руководитель» для согласования переработки — РОП отдела, директор, или по иерархии должностей?
3. Автосчёт онлайн: считать активностью только клики в платформе, или «открыта вкладка»=онлайн? Что при простое?
4. Округление: «полные часы согласно контракта» — округлять фактическое время вниз до часа? до нормы?
5. Кто заполняет коды невыходов (О/Б/К/А) — сам сотрудник (заявка), HR-исполнитель (как Жуковская), или из 1С?
