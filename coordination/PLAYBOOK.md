## 1. Что происходит САМО (можно не думать об этом)

**При старте любой сессии Claude Code в этом проекте:**
- В контекст впрыскивается состояние флота: журнал активности, хотспоты, свежие пуши
  (`claude_awareness_hook.py`).
- Плюс здоровье окружения (`scripts/session_health.py`): живы ли dev-серверы (:8000/:3210),
  свежи ли метки readiness/STATUS, когда была последняя ретроспектива. Если что-то
  протухло — ассистент обязан сказать об этом первой строкой. **Это замена Telegram-дайджеста:**
  статус приходит, когда ты садишься работать, а не в мессенджер.

**При каждой правке кода ассистентом:**
- `claude_audit_guard_hook.py` (новый): не даст править файл, который прямо сейчас занят
  параллельной сессией (реестры `coordination/.touched-*.txt` свежее 8 часов); предупредит,
  если правка добавляет только import (форматтер её откатит); напомнит правила для файлов
  памяти. Также блокирует вызовы инструментов с заведомо битыми параметрами — с подсказкой,
  как правильно.
- `claude_quality_hook.py`: после правки .py — автоматический ruff --fix + проверка;
  файл записывается в реестр тронутых.

**При коммите/пуше:** хуки координации журналируют всё в `coordination/.activity.local.md`
и `PUSH-LOG.md`; guard не пустит >1 коммита в общую ветку без верификации (обход — только
через `/safe-push`, см. ниже).

PreToolUse-гард и журнал пушей теперь покрывают не только Bash, но и инструмент PowerShell
(штатный шелл проекта на Windows); SessionStart-хук различает источник запуска сессии
(startup/resume/clear/compact/fork) и на форке отдаёт сокращённый впрыск.

**При сжатии контекста (компакте):** `readiness.py --write` обновляет авто-блоки STATUS.md
(теперь без кракозябр).

**Больше НЕ работает (отключено 16.07 осознанно):** ночная ретроспектива `CRM-daily-review`
и утренний Telegram-дайджест `CRM-tg-digest` — дайджест никто не читал, крон был молча
мёртв 8 дней. Вернуть при желании: `schtasks /Change /TN "CRM-tg-digest" /ENABLE` (и
аналогично второй). Уведомления «сессия ждёт твоего ввода» в TG (`tg_notify_hook.py`) —
оставлены, это другая подсистема.

## 2. Ежедневные команды (запускать из корня проекта)

| Что нужно | Команда |
|---|---|
| Поднять dev-окружение (бэк+фронт) | `powershell -ExecutionPolicy Bypass -File scripts\dev-servers.ps1` |
| …перезапустить с нуля | то же + `-Restart` |
| …в демо-режиме цен | то же + `-Demo` |
| Пересобрать dev.db (стоп→удалить→сид→старт) | `powershell -ExecutionPolicy Bypass -File scripts\reseed-dev.ps1` |
| Гейты фронта (по изменённым файлам) | в `frontend/`: `npm run gates` |
| Гейты фронта (весь сьют, перед коммитом) | `npm run gates:full` |
| Гейты питона (ruff+pytest) | `powershell -ExecutionPolicy Bypass -File scripts\gate-py.ps1` (можно указать тест-файлы) |
| Свежие метрики готовности | `.venv\Scripts\python.exe scripts\readiness.py --write` |

Запускать серверы «просто командой в чате» больше не надо: скрипт идемпотентен (повторный
запуск скажет «уже подняты») и сам ждёт health. Бэкенд теперь с авто-перезагрузкой
(`--reload`): новые роуты подхватываются без рестарта.

## 3. Как ставить задачи ассистенту (вместо «сделай 4 цикла улучшений…»)

- **`/cycles 4 лиды`** — контрактные циклы: ассистент сначала пишет нумерованный план в
  `PLAN.md`, утверждает состав и критерий остановки одним вопросом, работает, и каждые
  2 цикла даёт чек-пойнт «продолжаю/стоп». Развилки дизайна (дубль существующей ручки,
  вторая однотипная панель, чувствительные данные) он обязан спросить ДО реализации —
  ответы копятся в `coordination/DECISIONS.md` и не переспрашиваются.
- Однословное **«делай»/«давай»** = «продолжай последний утверждённый пункт PLAN.md»
  (записано в CLAUDE.md, ассистент не будет заново анализировать модуль).
- Закрытие цикла (гейты→коммит→ревью) ассистент делает по skill **`ship-cycle`** — один
  стандарт вместо ручного ритуала. ⚠️ С 2.1.215 Claude не запускает `/code-review` и `/verify`
  сам — в `ship-cycle` они стоят явными шагами. `/code-review` с 2.1.218 идёт фоновым
  сабагентом, результат приходит уведомлением.

## 4. Пуш в общую ветку

- **`/safe-push sales-2.0-redesign`** — единственный правильный способ. Скрипт сам:
  fetch → временный worktree от origin → cherry-pick только ТВОИХ коммитов → проверка
  авторства → push → уборка. Любой сбой = ничего не запушено, главный чекаут не тронут
  (случай bc10ff6 больше невозможен). Если коммит двигал submodule — сначала пушится
  репо субмодуля (скрипт предупредит).

## 5. Гигиена сессий (главная экономия токенов)

- **Правило:** сессия пережила 2 компакции ИЛИ живёт 3-й день → закрой её на вехе (пуш,
  отчёт) и открой новую. Контекст передаётся через `coordination/COORDINATOR-RESUME.md`,
  память и STATUS.md — ничего не теряется. За неделю аудита две вечные сессии съели 91%
  всех cache-read токенов.
- **⚠ 1M контекста у Opus 5 правило НЕ отменяет.** Cache-read платится за КАЖДЫЙ ход, и чем
  больше накоплено контекста, тем дороже каждый следующий ход. 1M — это запас на разовую
  широкую задачу (прочитать большое дерево, собрать граф), а не разрешение жить в одной
  сессии вечно. Контрольная цифра: 45 дней флота = 20,8 млрд cache-read токенов.
- **Чем закрывать сессию (новое в CC 2.1.191–2.1.218):**
  - `/fork` — копирует текущий диалог в НОВУЮ фоновую сессию. Лучший способ «отпочковать»
    побочную ветку работы, не убивая основную и не пересказывая контекст руками.
  - `/rewind` — откат по истории, теперь умеет доставать состояние и до `/clear`.
  - `/resume` — пикер прошлых сессий, если закрыл не то.
  - `/context` после компакции показывает актуальные цифры (раньше врал докомпактными).
- Тиринг моделей — [MODEL-TIERING.md](MODEL-TIERING.md): основная сессия думает, рутину
  делают Haiku/Sonnet-субагенты, тяжёлую проверку — Opus-СУБАГЕНТ (не переключай `/model`
  у основной сессии посреди работы).

## 6. Фоновые задачи (spawn_task / worktree-сессии)

**Что нужно знать про фон:** сабагенты по умолчанию фоновые (с 2.1.198); фоновая сессия умеет
ЗАПРОСИТЬ ввод (2.1.216) — молчание не всегда зависание; потолки 20 одновременных / 200 спавнов
на сессию / вложенность 3 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` отключает); `--max-budget-usd`
с 2.1.217 реально останавливает фоновых сабагентов; скилл с frontmatter `context: fork` уходит в
фон, если не поставить `background: false`.

Первый шаг фоновой сессии в worktree:
`powershell -ExecutionPolicy Bypass -File <главный-чекаут>\scripts\bootstrap-worktree.ps1`
— перебазирует дерево на актуальную ветку (`git config aios.defaultBranch`, сейчас
`sales-2.0-redesign`), сделает junction node_modules, подтянет submodules. Грязное дерево
скрипт не трогает.

## 7. Браузер и скриншоты

- Скриншоты — **только Playwright MCP** (работает с `--isolated`: сессии больше не дерутся
  за профиль Chrome). Browser pane — только навигация/чтение текста. *(Частичная перепроверка
  25.07.2026 на CC 2.1.219: навигация и чтение DOM в Browser pane работают штатно; скриншот
  измерить не удалось — в неинтерактивной сессии панель не отображается. Правило в силе,
  один замер в живой сессии его подтвердит или снимет — детали в CLAUDE.md.)*
- HTML-макеты — только через `http.server` (launch.json `static-mockups`, :8791);
  `file://` в Playwright заблокирован.
- Если после обновления плагина Playwright вернулась ошибка «Browser is already in use» —
  снова добавить `--isolated` в args (см. CLAUDE.md).

## 8. Если что-то сломалось

- Ошибка `InputValidationError` у инструментов — сигнатуры в памяти `tool-signatures.md`;
  хук должен был поймать раньше API.
- Хук мешает легитимной правке чужого файла (сессия-владелец уже умерла):
  `AIOS_ALLOW_FOREIGN_EDIT=1` — осознанный обход.
- Кириллица кракозябрами в консоли — не должно повторяться (PYTHONUTF8=1 в settings.json,
  ASCII-вывод хуков); если видишь — это баг, показать ассистенту. С 25.07.2026 хуки не
  полагаются на env: `claude_guard_hook.py` сам переключает stdout/stderr в UTF-8 и читает
  stdin байтами, потому что воркеры получают гард через `--settings` без блока env.
- Восстановление регистрации хуков на другой машине: `.claude/settings.json` в .gitignore,
  эталон — `.claude/settings.json.example` (версионируется), восстановление — скопировать
  его в `.claude/settings.json`.
