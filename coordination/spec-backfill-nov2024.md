## ⚠ Критичный контракт — исторические даты

`Deal.stage_changed_at` имеет `server_default=now()`, и `POST /sales/deals` не даёт задать
`created_at`/`stage_changed_at`. **Если лить ноябрь-2024 через API — все won-сделки лягут в
текущий месяц** и испортят План/Факт, `/rop/plan-fact`, аналитику стадий.

Поэтому сделки/сообщения — **скриптом с явными историческими датами** (`created_at`,
`stage_changed_at`, `closed_date` = даты из Bitrix). Образец ORM-наполнения — `scripts/seed.py`.
Скрипт класть в `connectors/` или `scripts/backfill_nov2024.py` (территория полосы).

## Швы (обязательные)

- **1С — строго чтение** (OData GET). Write заморожен.
- **Контрагенты — только через MDM-фасад** (`core/services/mdm.py`), склейка голова+филиалы по УНП.
- **`modules/integrations/**` не править** (синк-полоса). Новый эндпоинт там — через координатора.
- **finance** — писатель fin-7: платежи по её контракту, не напрямую в чужие таблицы.
- **Миграции** — номер только у координатора (новых таблиц по этой карте НЕ требуется).
- Секреты — `.env`, не коммитить. Скрипт должен быть идемпотентным (повторный прогон безопасен).

## Порядок прогона (рекомендуемый)

1. Контрагенты → MDM (п.1) — фундамент связей.
2. Сделки (п.2) → сообщения/звонки (п.3, 4).
3. Платежи (п.5) — после сделок (связь по счёту/контрагенту).
4. Сырьё RAG (п.6) — параллельно в любой момент.
