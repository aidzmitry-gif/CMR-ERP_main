# Задание воркеру `rop-stages`

Ты строишь demo-экран РОП **«Этапы воронки · старение сделок»** для CRM (Next.js App Router,
Tailwind). Витрина концепта на demo-данных. Цель (goal-driven): **создать страницу + файл данных
так, чтобы `npx tsc --noEmit` был зелёным и маршрут `/crm/rop/stages` компилировался, а стиль
совпадал с эталоном `cash/page.tsx`.** Идея экрана РОПа: показать, ГДЕ воронка «гниёт» —
сделки, превысившие норматив (SLA) этапа.

## СНАЧАЛА прочитай (контекст и стиль — не угадывай)
- `frontend/src/app/crm/rop/cash/page.tsx` — ЭТАЛОН структуры/стиля (копируй паттерн карточек/таблиц).
- `frontend/src/components/rop/ui.tsx` — `Card, Caption, Tag, Bar, Dot, Avatar`, палитры `*_TONE`, тип `Tone`.
- `frontend/src/components/rop/rop-tabs.tsx` — `RopTabs`; ключ `"stages"` УЖЕ в union — НЕ менять.
- `frontend/src/lib/rop-data.ts` — посмотреть форму данных; взять `import type { Tone }`.

### `frontend/src/app/crm/rop/stages/page.tsx`
Серверный компонент (без `"use client"`/хуков/onClick). Структура как `cash/page.tsx`:
- `AppShell crumbs={["CRM", "РОП", "Этапы воронки"]}`, `main ... bg-canvas p-6`, контейнер
  `mx-auto max-w-[1220px] space-y-4`, h1 + подзаголовок, `<RopTabs active="stages" />`.
- Блок 1 — «Старение по этапам»: по каждому этапу строка с нормой/факт-днями (`Bar` = факт vs норма,
  красный если превышено) и счётчиком «N сверх SLA» как `Tag` (тон по этапу). Согласование подсветить «узкое место».
- Блок 2 — «Зависшие сделки» (список как attention в cash): клиент + `Avatar`/менеджер + `Tag`
  «этап · Xд (норма Yд)» тоном; отсортируй по превышению. 
- Блок 3 — «Конверсия по этапам» (как воронка в Обзоре): этапы со счётчиком и `Bar` (ширина = доля от 68),
  подписи конверсий, пометка узкого места (Согласование 37%). Строка-инсайт снизу.
- Цвета — только через палитры, hex не хардкодить. Таблицы/списки широкие — `overflow-x-auto`+`min-w`, `th scope="col"`.
