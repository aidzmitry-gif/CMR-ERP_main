# board-stage-move — задание воркеру

Файл-макет: **`sales-board-mockup.html`** (корень репо, self-contained HTML, inline CSS/JS, открывается офлайн). Это доска сделок CRM (канбан по стадиям воронки). Бэкенда нет — всё в браузерном JS.

## Цель (Goal-Driven)
Сейчас в drawer-предпросмотре (открывается 1 кликом по карточке) кнопка **«→ Следующая стадия»** вызывает `drawerStage()`, которая только показывает toast. Сделай так, чтобы она **реально перемещала карточку в следующую колонку воронки** и обновляла её стадию, затем закрывала drawer и показывала toast «Стадия → <название>».

Сформулируй как проверку: «открыл карточку → нажал "→ Следующая стадия" → карточка физически переехала в следующую колонку, бейдж/стадия обновились, drawer закрылся, toast показал новую стадию; на терминальной стадии — не двигается, toast сообщает что дальше некуда».

## Что уже есть в файле (изучи перед правкой)
- `STAGES` — массив стадий воронки (порядок). Колонки доски рендерятся `renderBoard()` из данных.
- `openDrawer(card)` — открывает drawer, кладёт карту в `window._lastCard`.
- `readCard(card)` — читает данные карточки из DOM (в т.ч. стадию `stageTitle`).
- `drawerStage()` — текущая заглушка (toast). Её и переписать.
- `toast(msg)` — уже есть.
- Карточки — DOM-элементы `.card` внутри колонок воронки; колонки соответствуют стадиям.

## Подход (на твоё усмотрение, но Surgical)
Вариант А (проще, надёжнее для макета): по `window._lastCard` определить текущую стадию, найти следующую в порядке колонок воронки, **переместить DOM-узел карточки** в DOM следующей колонки (appendChild в её контейнер карточек), обновить видимый бейдж стадии на карточке, закрыть drawer, toast. Учесть, что у доски есть разные виды (по стадиям / по датам) — двигать осмысленно работает в стадийном виде; если текущий вид не стадийный — допустимо toast «доступно в виде по стадиям» (без поломки).
Вариант Б: обновить модель данных и вызвать `renderBoard()`.
Выбери проще и надёжнее. Терминальную стадию (последнюю/успех/отказ) не превышать.
