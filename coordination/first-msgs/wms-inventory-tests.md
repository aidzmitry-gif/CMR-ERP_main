# wms-inventory-tests — задание

## Цель (Goal-Driven)

**Напиши тесты на жизненный цикл инвентаризации склада → сделай их зелёными.**

В модуле `wms` 42 эндпоинта, тестами задето 15. Полностью без тестов остался цикл
инвентаризации — самая длинная цепочка состояний в модуле, и именно там дефект дороже
всего: расхождение остатков означает неверные деньги в отчётах.

Не покрыто (проверено по `modules/wms/routes.py`):

| Эндпоинт | Что делает |
|---|---|
| `GET  /wms/inventory/{count_id}` | карточка пересчёта |
| `POST /wms/inventory/{count_id}/populate` | наполнить строками из текущих остатков |
| `POST /wms/inventory/{count_id}/lines` | добавить строку вручную |
| `PATCH /wms/inventory/lines/{line_id}` | вписать фактическое количество |
| `POST /wms/inventory/{count_id}/complete` | закрыть пересчёт, провести расхождения |

`POST/GET /wms/inventory` (создание и список) уже покрыты в `tests/test_wms_round5.py` —
переписывать не надо.

## Что сделать

Один новый файл `tests/test_wms_inventory.py`. Веди его по циклу LOOP: сначала RED-тест,
потом зелень. Эталон стиля, фикстур и маркеров — `tests/test_wms_round5.py`, работай по нему,
свои конвенции не изобретай.

Покрой как минимум:

1. **Сквозной путь:** создать пересчёт → `populate` из остатков → строки появились с
   ожидаемым «учётным» количеством → вписать факт, отличный от учёта → `complete` →
   остаток изменился ровно на расхождение.
2. **Строка вручную:** добавить строку по SKU, которого не было в `populate`.
3. **Границы:** `complete` уже закрытого пересчёта; `PATCH` несуществующей строки;
   `GET` несуществующего `count_id`. Ожидаемый ответ бери из кода роутов, не выдумывай.
4. **Идемпотентность `populate`:** повторный вызов не должен дублировать строки
   (если код так не умеет — см. раздел про дефекты, это находка, а не повод чинить).

## Если нашёл настоящий дефект продукта

**Не чини.** `modules/**` вне скоупа: файл `routes.py` — 1592 строки, его правят другие полосы,
и твоя правка встретится с чужой. Вместо этого:

1. Пометь ровно этот один тест `@pytest.mark.xfail(strict=True, reason="...")` с одной
   строкой сути и ссылкой на свой status-файл.
2. Опиши сценарий в `## PITFALLS-DISCOVERED` своего status-файла: что вызвал, что ожидал,
   что получил.
3. Доложи строкой `КООРД: NEEDS-ARB wms-inventory-tests — <суть дефекта>`.

Остальные тесты при этом должны быть зелёными.

## Критерий готовности

- `pytest tests/test_wms_inventory.py -x` → 0
- `pytest -q` целиком остаётся зелёным (ничего не сломал соседям)
- `ruff check .` чист
- тронуты ТОЛЬКО `tests/test_wms_inventory.py` (+ status-файл)
- баннер `STATE: COMPLETE` в конце status-файла
