# Тиринг моделей — политика флота

> Кто на какой модели работает. Цель: **качество там, где цена ошибки высока; экономия токенов
> там, где работа механическая.** Правит координатор. Источник приоритетов — PLATFORM.md
> (деньги → безопасность → функции → эстетика): чем ближе задача к деньгам/безопасности — тем выше тир.

## Тиры

| Тир | Модель | Когда | Почему |
|-----|--------|-------|--------|
| **T1 — Opus** | `claude-opus-5` | Архитектура, схема БД/миграции, деньги (landed/маржа/проводки), безопасность/AuthZ, shared-kernel, контракты событий, **адверсариальная сверка**, арбитраж координатора | Цена ошибки высокая, нужна глубина |
| **T2 — Sonnet** | `claude-sonnet-5` | Обычная фича-разработка в своём модуле, порт HTML→React, роуты/CRUD, тесты, рефакторинг | Основной рабочий тир — баланс цена/качество |
| **T3 — Haiku** | `claude-haiku-4-5` | Механика: переименования, скаффолд, доки/markdown, простые тесты, широкие сканы-разведка, форматирование | Дёшево и быстро, рассуждать почти не надо |

> **Факт про чекаут координатора:** проектный `.claude/settings.json` пиннит `"model": "opus"` для всех сессий
> проекта — это осознанное решение оператора зафиксировать чекаут координатора на Opus, не критика и не повод
> его менять. Это НЕ отменяет правило «сабагенты и воркеры тирятся по задаче» из таблицы выше — наоборот,
> именно поэтому тир сабагента/воркера в ТЗ и вызовах задаётся ЯВНО, а не наследуется молча от чекаута.

> **Opus 5 $5/$25** · Fable 5 $10/$50. Haiku в 10× дешевле Fable — «эффективная модель» для рутины = **Haiku**, не Fable.
>
> **Opus 5 (`claude-opus-5`) — новый дефолтный Opus** (Claude Code 2.1.219, 24.07.2026). Цена та же, что у 4.8
> ($5/$25), но **1M контекста** и `effort` по умолчанию `high`. **Opus 4.8 и 4.7 — legacy**: новые полосы и ТЗ на
> них не сажать, в шаблонах писать `claude-opus-5`. Контексты: Opus 5 / Sonnet 5 / Fable 5 — 1M, Haiku 4.5 — 200k.

> демо оператору), и НИКОГДА — на фоновых воркерах и длинных прогонах. Opus 4.7 из fast mode убран, `/fast`
> применяется к Opus 5 и 4.8.
>
> **Fable 5 (`claude-fable-5`) — ВНЕ тиринга.** Это самый дорогой флагман («самая мощная модель», long-horizon
> ризонинг). Не дефолт и не «Opus++»: на 99% задач флота Opus 5 достаточно за половину цены. Звать точечно и
> осознанно, только если Opus доказанно не тянет. По умолчанию сабагенты Fable НЕ наследуют.
>

## Усилия (effort) — вторая ось, ОРТОГОНАЛЬНА модели

Модель = «какой мозг» (глубина/цена). **Effort = сколько модель думает перед ответом** (слайдер
Faster↔Smarter). Это РАЗНЫЕ рычаги: Haiku на `high` дёшево, но думает дольше; Opus на `low` быстро,
но дорого. Комбинируй под задачу, а не крути один в потолок.

| Effort | Для чего | Типовая связка |
|--------|----------|----------------|
| `low` | Механика без рассуждения: скаффолд, переименования, форматирование, простой grep-скан, сбор фактов | **Haiku + low** |
| `medium` | Обычная фича: CRUD, порт HTML→React, тесты по эталону, черновик | **Sonnet + medium** |
| `high` | Ревью, верификация с суждением, деньги/безопасность-логика, резолв нетривиального конфликта | **Sonnet + high** (под гейтом) / **Opus + high** (деньги/схема) |
| `xhigh` / `max` | Архитектура, адверсариальный судья, арбитраж форка/контракта, merge money-логики | **Opus + xhigh** |

- **Дефолт флота:** сабагент-рутина — `Haiku + low`; рабочая фича — `Sonnet + medium`; T1-зона
  (деньги/безопасность/схема/судья) — `Opus + high`..`xhigh`. Fable — вне этого, точечно.
- Не наследовать эффорт главного цикла на механику: явный `effort: low` на груд-стадиях экономит без потери качества.
- Effort тиришь по СТАДИИ так же, как модель (см. шпаргалку ниже): find/extract → low, judge/verify → high.
- **⚠ Молчание ≠ дёшево.** У Opus 5 и Sonnet 5 в Claude Code `effort` по умолчанию = **`high`** (у Opus 4.8 — тоже
  high на всех поверхностях). Не указал `effort` на механической стадии — заплатил как за ревью. Поэтому `effort: low`
  на груд-стадиях пишем ЯВНО, а не надеемся на дефолт. Сабагенты и компакция наследуют thinking-конфиг главного
  цикла (CC 2.1.198) — глобальный `effortLevel: xhigh` в пользовательских настройках протекает во весь флот.

## В оркестрации координатора (мои сабагенты/воркфлоу)
- Сверка/судьи/вердикты по деньгам-безопасности — **T1** (Opus), `effort: high`.
- Чтение транскриптов/широкие сканы/сбор фактов — **T2/T3** (Sonnet/Haiku), `agentType: Explore`.
- Скаффолд/механические правки в воркфлоу — **T3**, `effort: low`.
- Правило: по умолчанию агент наследует модель главного цикла; **явно понижаю** тир на механике (экономия), **явно повышаю** до Opus на деньгах/безопасности/миграциях.
- **Обход тирится вниз:** gather (REPORTS/активность/git-состояние) + head-check делегирую **Sonnet**-сабагенту (`Explore`), он возвращает дайджест + флаги эскалации; на Opus остаются только эскалации (форк/спор/контракт/деньги) и подпись реестра. Оракул `alembic heads`==1 ловит форк машинно — отсюда «без потери качества». (Целиком на Sonnet можно и сам обход, если сессия на Sonnet; на арбитраже флипнуть `/model` вверх.)

## Лимиты платформы (Claude Code 2.1.219) — знать при планировании веера

Тиринг решает «кто думает», а лимиты — «сколько их одновременно». Планируешь фан-аут — сверься:

| Что | Значение | Как менять |
|---|---|---|
| Одновременных сабагентов | **20** | env `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (2.1.217) |
| Спавнов сабагентов на сессию | **200** | — (страховка от рант-away) |
| Вложенность сабагентов | **3 уровня** (дефолт платформы) | env `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` ЗАПРЕЩАЕТ вложенный спавн, не «капает» глубину (2.1.219) |
| Параллельность внутри одного Workflow | `min(16, ядра−2)` | лишнее встаёт в очередь, не теряется |
| Размер динамического воркфлоу | **medium = «меньше 15 агентов»** | Значение выбирается через `/config` → «Dynamic workflow size» в ИНТЕРАКТИВНОЙ сессии — там видны допустимые варианты; выбор сохраняется ключом `workflowSizeGuideline` в `settings.json`. Этот файл переносится/коммитится и работает в headless-воркерах. ⚠ Вслепую вписывать значение ключа не надо — допустимые значения в публичной документации не описаны |
| WebSearch на сессию | 200 | — |
| Бюджет прогона | `--max-budget-usd` | с 2.1.217 **реально останавливает** фоновых сабагентов |

- **Сабагенты по умолчанию ФОНОВЫЕ** (2.1.198): о завершении приходит уведомление, поллить их не надо
  и нельзя выдумывать их результат заранее. Фоновый агент умеет коммитить/пушить/открывать PR по завершении.
- **Вложенность 3** — это разрешение на нативную двухуровневую оркестрацию: координатор → лид полосы →
  воркеры, без внешнего `spawn_workers.py`. Правило выбора «натив vs headless-воркер» —
  [README.md](README.md), раздел «Что выбрать».
- **Дефолт «medium» появился в 2.1.219 и молча режет веер**: воркфлоу, которые раньше разворачивались на 20+
  агентов, теперь целятся в <15. Если полосе нужен широкий веер — выбрать нужное значение через `/config` в
  интерактивной сессии ЗАРАНЕЕ и закоммитить получившийся `settings.json`: в headless-воркерах `/config`
  недоступен, но сохранённый ключ `workflowSizeGuideline` там читается и работает.

## Как наращивать Sonnet без потери качества (операционные правила)

**Принцип:** Sonnet безопасен там, где результат **дёшево проверяем** или малоинтерпретируем. Качество даёт ВЕРИФИКАТОР, не модель. Есть оракул → можно Sonnet; нет оракула → Opus.

1. **Тирь по СТАДИЯМ воркфлоу, не по задаче целиком.** В одном воркфлоу: find / extract / classify / простой-union / черновик → **Sonnet**; judge / verify / синтез / merge money-логики / контракты → **Opus**. (Самый большой рычаг: реконсиляция 22ф×2 ~2.7M Opus — простые union шли бы на Sonnet, Opus только на core-refs.)
2. **Связка «Sonnet делает → гейт проверяет».** Оракулы проекта: `structured-output schema`, `grep '^<<<<<<<'==0`, `import main`, `lane_check.py` (ruff→tsc→pytest), adversarial-verify. Под гейтом ошибку ловит машина, не человек — отсюда «без потери качества».
3. **Каскад Sonnet-первым, эскалация на провале гейта.** Фейлы (тест красный / конфликт / refused) перезапускай на Opus ПОЭЛЕМЕНТНО — Opus трогает только не вытянутое; риск = «поймали+переделали», не «залили кривое».
4. **Генераторы Sonnet, судья Opus.** В adversarial-паттернах: finder'ы Sonnet, судья Opus (ловить правдоподобно-но-неверно — дорого ошибиться).
5. **Калибровка разово:** новый тип задачи — прогон на ОБЕИХ моделях, сверка. Совпало → тип на Sonnet навсегда. Доказательство, не вера.
6. **Каждое ТЗ несёт блок «Модель по стадиям».** Координатор при написании ТЗ классифицирует стадии задачи и пишет их прямо в файл (рядом с DoD): механика (CRUD/порт HTML→React/тест-скаффолд/чтение-оценка/подписчик под ЗАМОРОЖЕННЫМ контрактом/вызов готового фасада) → **Sonnet** с НАЗВАННЫМ гейтом (`lane_check.py`/`import main`/`alembic heads==1`/каскад-тест); деньги-логика/схема-миграция/контракт-события/безопасность-RBAC/GO → **Opus**. Так лейн видит модель в самой задаче и не дефолтит на Opus; гейт держит качество. Чисто-механическое ТЗ = «целиком Sonnet под гейтом X»; смешанное = стадии явно (пример — засев HR payroll). Каскад: Sonnet-первым → провал гейта эскалирует ЭЛЕМЕНТ на Opus.

### Стадии воркфлоу → модель (шпаргалка)
| Стадия | Модель |
|---|---|
| Извлечение из кода (граф событий, dirty-разбор), классификация diff'ов | **Sonnet** |
| Резолв конфликтов: мокапы / доки / простой union / 1 хунк | **Sonnet** |
| Черновики ТЗ (грунтованные) → сверка контрактов | **Sonnet → Opus** |
| Оценка готовности (чтение+прикидка), фронт-UX, CRUD по эталону, тест-скаффолд | **Sonnet** |
| Обход координатора: чтение REPORTS/активности, детект новых, head-check (оракул `alembic heads`), мех-правки реестра | **Sonnet** |
| Merge money-логики, контракты событий, схема/миграции, GO-решения, синтез, судья, арбитраж форка/контракта | **Opus** |

### ⚠ Прецедент под Ultracode
**Ultracode ≠ «Opus на всё».** Ultracode задаёт ГЛУБИНУ/ШИРОТУ/ВЕРИФИКАЦИЮ (число агентов, раунды, адверсариальность), а НЕ модель на каждой стадии. Механические стадии тирятся вниз (Sonnet/Haiku) **ДАЖЕ под Ultracode**; на Opus остаются только T1-стадии (деньги/безопасность/схема/merge-логика/судья). Тщательность и тиринг — ортогональны, не выключай Ultracode ради экономии — тирь стадии.

## Экономия (почему это в деньгах и токенах)
- Не гонять Opus на механике — прямая экономия токенов без потери качества.
- Не экономить на T1-зонах (деньги/безопасность/схема) — ошибка там дороже сэкономленных токенов (PLATFORM.md #1–2).
- Тир — на ЗАДАЧУ, не на полосу: одна полоса может крутить T2, а на миграции поднять до T1.
