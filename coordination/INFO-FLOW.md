# INFO-FLOW — как сессии и модули обмениваются информацией

> Канон. Новая параллельная сессия читает это ПЕРЕД работой. Два разных плана —
> не путать: **чаты** (сессии) обмениваются иначе, чем **модули** (код).

## TL;DR

- Между **чатами** живого канала нет — обмен **асинхронный, через файлы + git** (читай перед,
  пиши после). Полнота зависит от дисциплины → часть её теперь **автоматизирована git-хуками**.
- Между **модулями** в рантайме — только шина событий (outbox) + фасад `Core`. См.
  [DEPENDENCY-MAP.md](DEPENDENCY-MAP.md) §1–§3.

---

## План А — между чатами (dev-time)

Общая «доска» — папка `coordination/`. Никто не «созванивается», обмен записями:

| Артефакт | Что несёт |
|---|---|
| [DEPENDENCY-MAP.md](DEPENDENCY-MAP.md) | Реестр **появившихся взаимодействий**: граф событий §2, shared-kernel §3, хотспоты §5. Новая связь → правишь файл. |
| `ACTIVE-SESSIONS.md` | Каждая сессия регистрирует **свою полосу файлов**. |
| `<name>-scope.md` + `first-msgs/<name>.md` | Вход воркеру (ТЗ + первое сообщение). |
| `<name>-status.md` | Выход воркера: прогресс + баннер `STATE: COMPLETE/BLOCKED/NEEDS-ORCHESTRATOR-ANSWER`. |
| `memory/pitfalls.md` | Память флота: `spawn` вшивает в КАЖДЫЙ промпт, `integrate` авто-собирает новые грабли. |
| **`.activity.local.md`** | **Авто-журнал «что сделано»** (git-хуки, не трекается). См. ниже. |
| git: commit / branch / PR | Сигнал «готово» наружу. Push — **только свой коммит** (cherry-pick на ветку от `origin/main`). |

## План Б — между модулями (runtime)

Модули **не импортируют** друг друга. Два легальных канала:
- **Канал A — события (outbox):** `event_bus.emit(session, type, payload)` → `outbox_event` в той же
  транзакции → фоновый relay (2с) → подписчики + `AuditLog`.
- **Канал B — фасад `Core`** при `register(core)`: роуты/подписки/воркфлоу/RBAC.
- **Shared kernel** (`counterparty`, `sku`, `app_user`, `ref_*`): FK на ядро, не копировать.

Dev-time у субмодулей: правка модуля = коммит в его репо + **сдвиг указателя** в суперпроекте.

## Автоматизация на commit / push (git-хуки)

`core.hooksPath = .githooks` → хуки [`post-commit`](../.githooks/post-commit) и
[`pre-push`](../.githooks/pre-push) зовут [`scripts/coordination_hook.py`](../scripts/coordination_hook.py).
Работают для **всех** акторов (мои сессии, ручной коммит, воркеры в worktree'ах).

**На каждый commit** — строка в `coordination/.activity.local.md` (общий журнал флота на машине,
лежит в ГЛАВНОМ worktree, виден из linked-worktree). Если коммит задел **хотспот /
shared-kernel / миграцию / добавил событие шины** — печатает напоминание обновить
`DEPENDENCY-MAP.md` и `ACTIVE-SESSIONS.md`.

**На каждый push** — фиксирует диапазон в журнал + те же флаги; если коммитов >1 — мягко
предупреждает «пушь только свою полосу». **Никогда не блокирует** commit/push (любая ошибка → no-op).

### Субмодули — знают через сдвиг указателя (не напрямую)

Git-хуки **не рекурсивны**: `core.hooksPath` живёт в суперпроекте, а каждый из 9 субмодулей —
отдельный репо со своим (пустым) конфигом. Поэтому коммит **внутри** субмодуля
(`cd modules/sales && git commit`) хук суперпроекта НЕ ловит.

Ловится **сдвиг указателя** в суперпроекте (`git add modules/<name> && git commit`) — это и есть
канонический сигнал «субмодуль продвинулся» (план Б). Хук **submodule-aware**: видя сдвиг gitlink,
он заглядывает внутрь субмодуля по его object store, пишет в журнал новые коммиты строкой
`└ submodule modules/<name>: N нов. коммит(ов)` и гоняет детектор флагов по ВНУТРЕННЕМУ диффу
(новый `emit`/`subscribe` внутри субмодуля → флаг «обнови граф §2»).

> Хочешь флаги уже на коммите ВНУТРИ субмодуля (до сдвига указателя) — поставь хук и в субмодули:
> `git submodule foreach 'git config core.hooksPath ../../.githooks'`. Минус: хрупко (`git submodule
> update`/re-init сбрасывает конфиг) и требует трогать 9 репо. По умолчанию — НЕ ставим, хватает
> чокпоинта суперпроекта.

### Включить в свежем клоне / новом worktree

```sh
git config core.hooksPath .githooks
```

Журнал `.activity.local.md` — локальный (в `.gitignore`); сами хуки и скрипт трекаются,
поэтому едут со всеми. Выключить разово: `git config --unset core.hooksPath`.

## Перед стартом новой сессии (чек-лист)

1. Прочитать этот файл + [DEPENDENCY-MAP.md](DEPENDENCY-MAP.md).
2. Назвать свою полосу файлов в `ACTIVE-SESSIONS.md`, свериться с хотспотами §5 и чужими полосами.
3. Глянуть `.activity.local.md` — что недавно делали другие сессии.
4. Менять shared-kernel / контракт центрального события / брать номер миграции — только сверившись.
