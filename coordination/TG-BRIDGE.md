# Telegram-мост к оркестратору (`tg_bridge.py`)

Управляй параллельными Claude-воркерами и получай уведомления живых VSCode-чатов
прямо из Telegram, не путая «чаты». **Топик форум-группы = воркер.** Отдельный
топик «💬 VSCode» = уведомления интерактивных сессий.

Это надстройка над `spawn_workers.py` (см. `coordination/README.md`): бот импортирует
его внутренности, поэтому состояния воркеров (LIVE/IDLE/STALE/COMPLETE/NEEDS-ANSWER/
BLOCKED) — ровно те же, что в `status`.

## Что умеет

**A. Оркестратор ↔ Telegram (двусторонне)**
- следит за состояниями воркеров и шлёт в топик воркера только значимое:
  🟠 нужен ответ (с текстом вопроса), ✅ готов к интеграции, ❌ заблокирован, 🔴 завис;
- **обычный текст в топике воркера = ответ воркеру** → `respond` (стоп, дописать ответ
  в first-msg, пере-spawn в том же worktree);
- команды: `/status` `/workers` `/tail <имя> [n]` `/spawn <имена>` `/integrate <имя>`
  `/cleanup <имя>` `/stop <имя>` `/respond <имя> <текст>` `/help`.
- сессии (вариант B): `/sessions` `/attach <№|id>` `/new [путь]` `/detach`.

**B. Продолжение твоих сессий Claude Code (handoff, двусторонне)**
- `/sessions` — список недавних сессий; `/attach <№|id>` — привязать сессию к топику;
  дальше пишешь обычный текст → `claude -p --resume <id>` продолжает **ту же** сессию
  (тот же id, весь контекст). `/new [путь]` — начать новую сессию в папке.
- Это **передача эстафеты**: на компе `claude --resume <id>` подхватит всё, что
  наработано из Telegram, и наоборот. НЕ одновременная работа в одном живом окне.

**C. Уведомления живых VSCode-чатов (только пуши)**
- hook `Notification` (срабатывает, когда чат ждёт ввода/разрешения) пишет событие в
  `coordination/.tg-events.jsonl`, бот пересылает его в топик «💬 VSCode» с пометкой
  проекта и id сессии. Печатать ответ всё равно в VSCode — Claude Code не даёт
  «впрыснуть» сообщение в живую интерактивную сессию (см. §Ограничения).

## Настройка (5 минут)

1. **Создать бота.** В Telegram напиши [@BotFather](https://t.me/BotFather) →
   `/newbot` → получишь токен.
2. **Группа с топиками.** Создай группу, в настройках включи **Topics** (Темы).
   Добавь бота в группу и сделай его **админом** с правом *Manage Topics*
   (создавать темы) — иначе топики не создадутся и мост откатится в режим одного чата.
3. **`.env`.** Скопируй строки из `tg_bridge.env.example` в `.env` (корень репо),
   впиши `TG_BOT_TOKEN`.
4. **Узнать `TG_CHAT_ID`.** Запусти и напиши что-нибудь в группу:
   ```powershell
   & ".\.venv\Scripts\python.exe" tg_bridge.py --probe
   ```
   Он напечатает `TG_CHAT_ID=...` и твой `from=<user id>`. Впиши оба в `.env`
   (`TG_CHAT_ID`, и по желанию `TG_ALLOWED_USER_IDS`).
5. **Запустить мост:**
   ```powershell
   & ".\.venv\Scripts\python.exe" tg_bridge.py
   ```
   В группе появится «🟢 Мост запущен». Дальше — `/help`.

## Включить Часть C (уведомления VSCode-чатов)

Хук НЕ ставится автоматически (это правка стартового конфига Claude Code). Вставь
вручную блок `hooks` в один из файлов:

- **только этот проект:** `.claude/settings.json` в корне репо;
- **все твои проекты/чаты:** `~/.claude/settings.json` (`C:\Users\<ты>\.claude\settings.json`).

```json
{
  "hooks": {
    "Notification": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python \"d:\\6 Проекты\\CRM ERP\\Сlaude CRM - проект\\tg_notify_hook.py\""
          }
        ]
      }
    ]
  }
}
```

(если в файле уже есть другие ключи, напр. `"model": "opus"`, просто добавь ключ
`"hooks"` рядом, не затирая остальное). Путь к `tg_notify_hook.py` оставь абсолютным —
тогда события из сессий любых проектов лягут в очередь этого репо.

## Запускать в фоне

Самое простое — отдельное окно PowerShell, которое не закрываешь. Либо как фоновую
задачу. Мост держит состояние в `coordination/.tg-bridge-state.json` (оффсеты,
карта топиков) и переживает перезапуск без потери контекста.

## Вариант B по шагам

1. `/sessions` — бот покажет недавние сессии (проект + последняя реплика), нумерованные.
2. `/attach 2` (или `/attach <id-префикс>`) — привязать к топику. В форуме, если дать
   команду в General, бот заведёт отдельный топик «🧠 <проект>».
3. Пиши в этот топик обычным текстом — Claude продолжит **ту же** беседу, ответ придёт
   сюда же. Длинные ответы бьются на части.
4. `/new D:\путь\к\проекту` — начать новую сессию (без аргумента — этот репо).
5. На компе: `claude --resume <id>` (id виден в `/sessions`) — подхватишь всё с телефона.

Режим разрешений хода — `TG_B_PERMISSION_MODE` (деф. `acceptEdits`: авто-правки файлов,
но без запуска произвольных команд). Нужен полный автоном с телефона (pytest/git) —
поставь `bypassPermissions` (трогает рабочий репо без спроса; см. ниже).

## Защита: PreToolUse deny-гард (важно при bypass)

`claude_guard_hook.py` — жёсткий блок катастрофических действий агента, работает при
ЛЮБОМ режиме разрешений, включая `bypassPermissions`. Он **ничего не спрашивает**:
allow-by-default, молча режет только короткий список (rm -rf по корню, `curl|sh`,
чтение `.env`/`.ssh`/`~/.claude.json`, `tailscale ssh`/prod-IP, `git push --force`,
попытка отключить сам гард). Обычная работа (правки, тесты, commit, npm, удаление
build-папок, `--force-with-lease`) проходит без трения. Проверено вживую: под
`bypassPermissions` команда блокируется до выполнения. Блоки пишутся в
`coordination/.tg-guard-denied.jsonl`.

Два уровня: BASE (всегда) и STRICT (доп. `reset --hard`, `clean -fdx`, `docker down -v`,
`DROP TABLE`…) — включается env `CLAUDE_GUARD_STRICT=1`. Удалённые B-сессии (`tg_sessions.py`)
идут в STRICT автоматически; твой интерактив — нет (чтобы не мешать).

### Где гард включён

- **B-сессии — автоматически.** `tg_sessions.py` сам добавляет гард через `--settings`
  (файл `coordination/.guard-settings.json` генерится на лету). Ручной шаг не нужен.
  Отключить: env `TG_B_GUARD=0`.
- **Воркеры — ВКЛЮЧЕНО по умолчанию** (`spawn_workers.py`: воркер стартует с `--settings`
  на `.guard-settings.json` + `CLAUDE_GUARD_STRICT=1`, STRICT-тир — хардненинг под
  `bypassPermissions`). Отключить целиком: env `WORKER_GUARD=0`.
- **Твой интерактив в VS Code — по умолчанию НЕ включён.** И это осознанно: гард —
  отдельный python-процесс перед КАЖДЫМ вызовом инструмента (~0.25с/вызов, в основном
  старт python). На автономных ходах (минуты) это незаметно, но при глобальной установке
  размажется по всей твоей ручной работе. Ты у клавиатуры и так всё видишь, поэтому
  интерактив оставлен быстрым.

### Опционально: гард и на интерактив (глобально)

Если хочешь подстраховать и ручную работу — вставь блок в `~/.claude/settings.json`
(подставь СВОИ пути к python и хуку). Цена — ~0.25с на каждый Bash/Edit/Read. Чтобы
урезать накладные, можно убрать `Read` из `matcher` (самый частый вызов; чтение секретов
через `cat .env` в Bash всё равно ловится):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|Edit|Write|MultiEdit|Read|NotebookEdit",
        "hooks": [
          {
            "type": "command",
            "command": "\"d:\\6 Проекты\\CRM ERP\\Сlaude CRM - проект\\.venv\\Scripts\\python.exe\" \"d:\\6 Проекты\\CRM ERP\\Сlaude CRM - проект\\claude_guard_hook.py\""
          }
        ]
      }
    ]
  }
}
```

(если в файле уже есть `hooks` с `Notification` из Части C — добавь ключ `PreToolUse`
рядом, не затирая). Тонко настроить списки — правь `claude_guard_hook.py` (`_BASE_BASH`,
`_STRICT_BASH`, `_SECRET_FILE`).

> Гард — это defense-in-depth, не абсолют (deny-лист обходится обфускацией). Сильнее
> всего он работает В СВЯЗКЕ с allowlist (`TG_ALLOWED_USER_IDS`), 2FA на Telegram и
> песочницей без доступа к секретам/проду.

## Ограничения (честно)

- **Нельзя** управлять из Telegram ТЕКУЩИМ открытым живым окном VSCode-чата в реальном
  времени (вводить за тебя и видеть это в окне) — у Claude Code нет API впрыска ввода в
  живую сессию. Вариант B — это **handoff по очереди**: продолжаешь ту же беседу с
  телефона, окно увидит изменения после `--resume`. Параллельно вести и окно, и телефон
  по одной сессии нельзя (разъедутся файлы/транскрипт).
- Воркеры (A) по умолчанию `bypassPermissions`, сессии (B) — `acceptEdits` (см. README
  §Безопасность). `/spawn` и `/new`/`/attach` исполняются на твоём аккаунте/подписке.
  Обязательно ограничь, кто может командовать ботом, через `TG_ALLOWED_USER_IDS`.

## Файлы

- `tg_bridge.py` — бот (импортирует `spawn_workers.py` и `tg_sessions.py`).
- `tg_sessions.py` — движок варианта B (resume сессий через CLI на подписке).
- `tg_notify_hook.py` — хук Notification → очередь событий.
- `claude_guard_hook.py` — PreToolUse deny-гард (блок опасного при bypass).
- `tg_bridge.env.example` — образец `.env`.
- `coordination/.tg-bridge-state.json`, `.tg-events.jsonl` — runtime (в `.gitignore`).
