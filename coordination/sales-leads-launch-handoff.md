Перед выкладкой CURSOR обязан проверить, что фактические gitlink-и сервера совпадают с этим
составом. Не брать релиз из грязного локального worktree.

## Что делает CURSOR на ERP-сервере

1. Зафиксировать точку отката: SHA суперпроекта, SHA субмодулей, текущую миграцию и статус
   контейнеров.
2. Выложить указанный состав по `coordination/RELEASE.md`; после старта убедиться, что
   `alembic heads` возвращает ровно одну голову.
3. Создать либо подтвердить учётные записи в Keycloak:
   - РОП: роль `sales_head`;
   - каждый менеджер: роль `sales`;
   - отдельная тестовая учётка без роли для проверки запрета доступа.
4. Проверить реальный вход: пользователь с ролью продаж получает 200 на `/crm/leads` и
   `/crm/deals`; пользователь без роли не получает доступ к данным.
5. Загрузить минимальные рабочие данные: контрагенты, контакты, номенклатура, цены,
   открытые сделки и лиды с назначенными менеджерами.
6. Провести smoke от имени менеджера:
   `создать лид → квалифицировать → назначить → конвертировать в сделку → добавить позицию
   → сформировать КП/счёт → зарегистрировать тестовую оплату → увидеть «Оплачено»`.
7. Подключить реальные каналы (сайт, почта, телефония) отдельным шагом. До этого отдел может
   работать с ручным вводом лидов.

## Что вернуть разработке

- фактический SHA и gitlink-и после выклада;
- вывод `/health`, `docker compose ps`, `alembic heads`;
- результат входа для `sales_head`, `sales` и пользователя без роли;
- результат сквозного smoke и серверные логи при любой ошибке.

Пароли, токены, строки подключения и содержимое `.env` в отчёт не передавать.
