# План проекта — AI-First Business Operating System

> Рабочее название: **AI-OS** (AI-First Business Operating System для B2B опта и производства).
> Первый клиент-эталон: оптово-производственная компания (аккумуляторы), Беларусь.
> Стратегия: один сильный вертикальный продукт → затем мультитенант на другие компании.

---

## 1. Краткое описание

Создаётся не классическая ERP/CRM, а **AI-First Business Operating System** — единая платформа, где:

- AI-агенты выполняют 70–90% операционной работы;
- все отделы связаны через **AI-оркестратор**;
- сотрудники занимаются контролем, approvals, стратегией и сложными кейсами.

Архитектурные принципы (фундамент закладывается сразу):
- **AI-first** — агенты и автоматизация в ядре, а не «прикручены сбоку»;
- **Event-driven** — всё через события и workflow;
- **Human-in-the-loop** — критичные действия подтверждает человек;
- **Unified Business Memory** — единая память (данные + знания + контекст) для всех агентов;
- **Multi-tenant ready** — с самого начала, чтобы потом подключать другие компании без переписывания.

Подход к запуску: **не строим все 13 модулей сразу**. Сначала — общая основа (ядро) и один сквозной рабочий модуль **SALES OS / CRM**, доведённый до реальной эксплуатации в компании. Затем последовательно добавляем модули по приоритету для бизнеса «опт + производство».

## 2. Целевая архитектура (из концепции)

| Слой | Технологии |
|------|-----------|
| Frontend | React, Next.js |
| Backend | Python, FastAPI |
| AI | GPT-класс модели + локальные LLM, RAG, LangGraph, CrewAI |
| Workflow / BPM | Flowable, Temporal |
| Хранилища | PostgreSQL, Redis, Qdrant (вектора), S3 |
| Аналитика | ClickHouse, Metabase / Superset |
| Шина сообщений | Kafka, RabbitMQ |
| Безопасность | RBAC, MFA, audit logs, SIEM, secrets management |

**Стратегия моделей:** local-first (embeddings, OCR, RAG, routing, summaries, мониторинг локально), API-fallback (сложный reasoning, premium, тяжёлый multimodal).

**Рекомендация по старту:** начать как **модульный монолит** (FastAPI, чёткие границы модулей) + Kafka для событий, выделяя в отдельные сервисы только то, что реально нагружено. Это быстрее, чем сразу микросервисы, и не мешает будущему разделению.

## 3. Дорожная карта по фазам

### ФАЗА 0 — Общая основа (Foundation / Core Platform)
Цель: платформа, в которую «втыкаются» все будущие модули и агенты.

- Монорепозиторий, окружения (dev/stage/prod), Docker, CI/CD.
- **Identity & Access:** аутентификация, RBAC, MFA, мультитенантность (изоляция данных по компаниям).
- **Базовая модель данных:** компании/тенанты, пользователи, роли, оргструктура.
- **Event bus** (Kafka/RabbitMQ) + базовый workflow-движок (Temporal или Flowable).
- **AI Orchestration Core (v0):** runtime агентов (LangGraph/CrewAI), реестр инструментов (tools), очередь задач для агентов, механизм **approvals (human-in-the-loop)**, **audit trail**.
- **Unified Business Memory (v0):** PostgreSQL + Qdrant (RAG) + S3 (файлы); единый слой контекста для агентов.
- **Omnichannel Gateway (skeleton):** единая точка для каналов (Telegram, WhatsApp, Viber, Email, телефония) — пока каркас.
- **UI Shell (Next.js):** layout с левым меню модулей (как на макете), дизайн-система, темы, навигация, auth.
- **Observability:** логирование, метрики, трейсинг, мониторинг затрат на LLM.

**Результат фазы:** пустой, но «живой» каркас системы с авторизацией, событиями, агент-движком и UI-оболочкой.

---

### ФАЗА 1 — SALES OS / CRM (MVP, фокус задачи)
Цель: довести до реальной работы блок продаж — **приём лидов, их распределение, ведение сделок, омниканальная коммуникация, интеграции, 3–5 AI-агентов**.

**Функциональность (из макетов):**
- **Мульти-воронки:** постоянные клиенты, новые клиенты, тендеры, проектные сделки.
- **Канбан сделок** со стадиями (Новая заявка → Квалификация → КП → Согласование → Закрыто) — drag&drop, фильтры, настройка воронки.
- **Карточка сделки:** компания, описание, сумма, приоритет, ответственный, след. шаг, дата/время, позиции номенклатуры, история, теги «Фокус»/«Приоритет».
- **Омниканальный инбокс:** переписка из WhatsApp / Viber / Telegram / Email / звонки в одной карточке («Все мессенджеры»).
- **Панель «Чаты и дела»** (как на макете) — единый список диалогов и задач.
- **«План на сегодня» / дашборд KPI:** звонки ключевым клиентам, всего звонков, план по сумме отгрузки, холодные звонки, обработка заявок, конверсия.
- **Приём лидов** из каналов: сайт/лендинги, Telegram, WhatsApp, Email, телефония, тендерные площадки.
- **Движок распределения лидов:** правила (география, продукт, нагрузка, тип воронки) + AI-роутинг.
- **Генерация КП** (коммерческих предложений) с подстановкой цен/наличия.

**Интеграции (ключевые для запуска):**
- **1С** — клиенты, контрагенты, номенклатура, цены, остатки, заказы/отгрузки, статусы оплат.
- **Альфа-Банк (Беларусь)** — выписки, поступления оплат, сверка платежей со сделками, статусы счетов.
- **Телефония** — звонки, запись, привязка к сделке.
- **Мессенджеры/Email** — через Omnichannel Gateway.

**AI-агенты блока CRM (3–5):**
1. **Lead Qualifier & Router** — принимает входящие лиды, обогащает данные, квалифицирует (целевой/нет), назначает воронку и распределяет менеджеру по правилам/нагрузке.
2. **SDR / Communication Agent** — ведёт переписку в каналах, отвечает на типовые вопросы, делает follow-up, договаривается о звонке/встрече (с approvals на важные сообщения).
3. **Pricing & КП Agent** — рассчитывает цену с учётом склада/1С/наценки, готовит КП, отслеживает рыночные цены (approval менеджера перед отправкой).
4. **Deal Coach / Forecast Agent** — оценивает вероятность сделки, подсказывает next-step, поднимает «зависшие» сделки, формирует прогноз.
5. **Manager KPI Controller** — следит за план/факт, KPI менеджеров, наполняет «План на сегодня», эскалирует отклонения.

> Human-in-the-loop: отправка КП, выставление цен, ключевые сообщения и смена стадии сделки — через подтверждение человека (настраиваемо).

**Результат фазы:** компания реально ведёт продажи в системе; агенты закрывают рутину по лидам и коммуникации; данные синхронизированы с 1С и банком.

### ФАЗА 2+ — Расширение по модулям (порядок под бизнес «опт + производство аккумуляторов»)

Приоритет — то, что сильнее всего влияет на оборот и маржу опта/производства:

1. **Master Nomenclature System** — единая номенклатура (SKU, дубли, категории, оборачиваемость, pricing). Фундамент для склада, закупок, продаж.
2. **WMS / Складской блок** — приёмка, размещение, сборка, отгрузка, инвентаризация, ABC/XYZ, прогноз дефицита, dead stock, trigger-sales.
3. **Procurement OS** — поиск поставщиков, мониторинг цен, переговоры, закупки, таможня; интеграции 1688/Alibaba/Taobao/Made-in-China/WeChat.
4. **Accounting / Finance Core** — интеграция 1С КА, проводки, ЭСЧФ, НДС, валютные операции, cash flow, бюджеты, прогноз кассовых разрывов.
5. **Transport & Logistics OS** — локальная доставка, Китай→РБ/РФ, консолидация, таможенные workflow, перевозчики, tracking.
6. **Office Manager + Document Flow** — документооборот, накладные, транспортные документы, approvals (DMS: OpenKM/Alfresco; BPM: Flowable).
7. **Legal OS** — проверка договоров, риски, претензии, debt collection, проверка контрагентов, compliance (право РБ).
8. **Marketing OS** — SEO, реклама, контент-фабрика, лиды, attribution, ROI.
9. **HRBP OS** — рекрутинг, онбординг, LMS, performance, аналитика сотрудников, выявление burnout.
10. **Knowledge Base + AI Memory (расширение)** — SOP, регламенты, шаблоны, обучение сотрудников.
11. **AI Orchestration Core (полная версия)** — сквозное управление агентами, workflow, approvals и KPI между всеми отделами.

### ФАЗА 3 — Мультитенант и тиражирование на другие компании
- Изоляция данных по тенантам, настраиваемые воронки/поля/роли.
- Конфигурируемые агенты и промпты под отрасль клиента.
- Каталог интеграций (коннекторы), биллинг, онбординг новых компаний.
- Шаблоны отраслевых конфигураций.

## 4. Сквозные направления (идут параллельно всем фазам)

- **Безопасность и комплаенс:** RBAC, MFA, audit logs, шифрование, secrets, защита перс. данных (РБ).
- **AI-надёжность:** guardrails, ограничение действий агентов, оценка качества ответов, fallback на человека, контроль затрат на LLM.
- **Качество данных:** дедупликация, нормализация номенклатуры/контрагентов (особенно стык с 1С).
- **Аналитика:** ClickHouse + Metabase/Superset, дашборды по продажам/KPI с первой фазы.
- **DevOps:** CI/CD, инфраструктура как код, бэкапы, мониторинг.

## 6. Риски и рекомендации

- **Слишком широкий охват.** Главный риск — пытаться сделать всё сразу. Жёстко держать рамки: Foundation + CRM до реальной эксплуатации, потом расширять.
- **Интеграция с 1С.** Часто самая трудоёмкая часть — заложить время на форматы обмена, нормализацию данных, тестовый контур 1С.
- **API Альфа-Банка (РБ).** Заранее проверить доступность API/выписок и условия подключения; при отсутствии — импорт выписок.
- **Точность AI.** Начинать с режима «AI предлагает — человек подтверждает», постепенно повышать автономность по мере накопления статистики качества.
- **Стоимость LLM.** Local-first для массовых операций, API только для сложного reasoning; мониторить расходы с первого дня.
- **Мультитенант.** Заложить изоляцию данных в Фазе 0, даже если первый клиент один — переделывать потом дорого.

## 7. Ближайшие шаги (первые 1–2 недели)

1. Зафиксировать **scope MVP CRM** и список интеграций для первого запуска.
2. Описать **реальные процессы продаж** компании (воронки, стадии, роли, KPI, правила распределения лидов).
3. Уточнить доступ к **1С** (конфигурация, способ обмена) и **API Альфа-Банка РБ**.
4. Поднять **каркас Фазы 0**: репозиторий, CI/CD, auth/RBAC, event bus, UI-оболочку с меню модулей.
5. Спроектировать **модель данных CRM** (лиды, сделки, клиенты, контакты, воронки, активности).
6. Выбрать и согласовать **первого AI-агента** для пилота (рекомендую Lead Qualifier & Router) и критерии его качества.
