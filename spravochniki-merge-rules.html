Правила слияния (survivorship)

Кто «побеждает» при конфликте источников — задаётся как данные, а не в коде. Для каждого поля: стратегия + приоритет источников. Так синк из 1С не затирает то, что закреплено за ЕГР, ERP или ручным вводом. Хранится в таблице survivorship_rule; применяется при импорте и merge.

Глобальный приоритет источников

Порядок доверия по умолчанию. Стратегия source_priority берёт первый доступный источник слева направо. Перетаскивание — в проде; здесь демонстрация порядка.

1 · 🏛 ЕГР› 2 · ✦ ERP› 3 · ✍ Вручную› 4 · 📥 1С› 5 · 🔵 Битрикс

Конституция данных: реквизиты — из госреестра (ЕГР); внутренние решения — за ERP; ручная правка важнее автосинка; 1С точен в УНП/деньгах; Битрикс — контакты, но не реквизиты.

Сущность

Правила задаются на сущность. Поля без своего правила берут стратегию по умолчанию (non_empty_wins).

Правила по полям — Контрагент

Поле Стратегия Приоритет / параметр Эффект при синке из 1С
УНП 🏛 только ЕГР 🛡 не трогает
Полное наименование 🏛 ЕГР › 📥 1С 🛡 не трогает (есть ЕГР)
Краткое наименование ✍ только вручную 🛡 не трогает
Юридический адрес 🏛 ЕГР 🛡 не трогает
Телефон самое свежее по дате ⚠ обновит, если 1С новее
e-mail непустое выигрывает — обновит, если в ERP пусто
Отрасль непустое выигрывает — синк обновит
Тип (клиент/поставщик) ✦ ERP 🛡 не трогает

source_priority

Берёт значение из самого приоритетного доступного источника. Для реквизитов: ЕГР → ERP → 1С.

manual_only

Меняется только человеком в ERP. Никакой синк не перезаписывает. Для выверенных вручную полей.

most_recent

Выигрывает самое свежее по дате изменения, независимо от источника. Для телефонов/контактов.

non_empty_wins

Дефолт: непустое значение замещает пустое; при конфликте двух непустых эталон сохраняется. Как сейчас в коде.
