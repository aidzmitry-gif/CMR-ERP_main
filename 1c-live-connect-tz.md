# ТЗ для агента (Cursor): подключить ЖИВУЮ 1С (ka_copy) к CRM — товары, цены, себестоимость

> Выполнять **на прод-сервере** (`/opt/cmr-erp`, Ubuntu, docker-стек `aios`), где 1С доступна по
> локальной сети. Ты — исполнитель; ниже весь контекст, сверенные факты и ограничения. Не спрашивай
> лишнего — действуй по задачам, на каждом шаге проверяй результат.

## 0. Обстановка (факты, проверены)
- **Сервер** в офисе, IP `192.168.89.83`, `/opt/cmr-erp`, ветка `main`, стек `aios` (Postgres + app),
  приложение при старте само гонит `alembic upgrade head`.
- **1С:** КА 2.4, база **`ka_copy`**, платформа 8.3.18. OData по локалке:
  **`http://192.168.89.14/ka_copy/odata/standard.odata/`**, пользователь **read-only** (HTTP Basic auth).
- Сервер и 1С — в одной LAN (`192.168.89.x`) → 1С достаётся напрямую, **Tailscale не нужен**.
- 🔴 **1С — СТРОГО ЧТЕНИЕ.** Никаких OData POST/PUT/PATCH в 1С. `post_document` не включать.
- 🔴 **`$filter` в этой файловой ИБ запрещён** → выборка окном по `$orderby=Date` + `$skip`
  (готовый приём — `scripts/import_month.py::onec_window`, бинарный поиск левой границы).
- 🔴 **Данные в `ka_copy` — только с окт. 2025** (ноябрь-2024 в другой, «свёрнутой» базе, её OData не
  опубликована). Тяни существующее окно (последние месяцы с данными).

## 1. Что УЖЕ есть в коде (переиспользовать, НЕ писать с нуля)
- **`scripts/import_month.py`** — рабочий ETL из 1С (+Bitrix), **поля сверены под `ka_copy`**:
  - `Catalog_Номенклатура`: поля `Ref_Key`, `Code`, `Description`.
  - `Document_РеализацияТоваровУслуг`: `Ref_Key`, `Date`, `Number`, `Posted`, `Контрагент_Key`,
    `СуммаДокумента`, таб.часть `Товары` со строками `{Номенклатура_Key, Цена, ЦенаСоСкидкой}`.
  - `Catalog_Контрагенты`: `Ref_Key`, `Description`, `НаименованиеПолное`, `ИНН`.
  - Приёмы: `onec_get`, `onec_window`, `onec_by_key` (`Catalog(guid'...')`), пагинация `$top/$skip`.
  - Цена SKU = последняя `ЦенаСоСкидкой || Цена` из строк проведённых реализаций за окно
    (`_load_sales_prices` → пишет `StockItem.price`, склад «Главный»).
- **`connectors/onec.py`** — универсальный OData-клиент (Basic auth, пагинация, ретраи).
- **`connectors/config.py`** — читает `connectors/.env`: `ONEC_BASE_URL`, `ONEC_USER`, `ONEC_PASSWORD`,
  список `ONEC_ENTITY_SETS` (регистр цен `InformationRegister_ЦеныНоменклатуры` там закомментирован).
- **`core/services/price_cost.py`** — **фасад ядра `PriceCostGateway`** (уже построен, коммиты PC1-6):
  контракт `async get_item_price_cost(session, sku_codes: list[str]) -> dict[str, ItemPriceCost]`, где
  `ItemPriceCost{cost_byn, price_byn, currency, price_type, as_of, source}`. Поле `core.services.price_cost`
  (None → честная деградация). **Потребители в `modules/sales` уже подключены** (маржа сделки `_deal_margin`,
  дефолт цены в КП, дефолт маржи конструктора плана; провенанс-метки «из 1С»/«демо»/«из закупок» в UI).
  То есть как только фасад отдаёт данные с `source='onec'` — карточка/подбор/план оживают сами.
- **`modules/integrations/client.py`** — `OneCClient` (реализует `OneCGateway`) — **сейчас MOCK**:
  все методы возвращают заглушки с `# TODO(part-6): при base_url — реальный OData GET`.
- **`modules/integrations/service.py`** — `sync_1c()` тянет контрагентов (через `reference_import` в MDM)
  и остатки/цены в `StockItem` + `Sku`. Регистрируется фасад `core.services.onec = OneCClient(base_url)`.
- **`core/services/onec.py`** — Protocol `OneCGateway` (контракт; impl — в integrations).

## 2. Цель
Чтобы в CRM появились **реальные данные из `ka_copy`** вместо демо:
1. **Товары** (номенклатура) — «Подбор товара» (`/sales/skus`) показывает настоящие позиции.
2. **Цены** — цена в марже/КП из 1С.
3. **Себестоимость** — себес в марже из 1С (регистр себеса найти на живой базе — поля НЕ сверены).

## 3. Задачи (по порядку)

### Z0 — проверить доступ к 1С с сервера
```bash
curl -s -u USER "http://192.168.89.14/ka_copy/odata/standard.odata/" | head -c 800
```
Ждём список сущностей (XML/JSON). 401 → креды; пусто/ошибка → сеть. Зафиксируй, что ответило.

### Z1 — прописать креды 1С (секреты — только на сервере, НЕ в git)
- В `connectors/.env` (рядом с `connectors/config.py`):
  `ONEC_BASE_URL=http://192.168.89.14/ka_copy/odata/standard.odata/`, `ONEC_USER=...`, `ONEC_PASSWORD=...`.
- Для приложения (стек): задать `AIOS_ONEC_BASE_URL` (+ при необходимости user/pass) в env docker-стека,
  чтобы `core.config.onec_base_url` был НЕ пуст (иначе `OneCClient` остаётся в mock).

### Z2 — залить реальные ТОВАРЫ + ЦЕНЫ (быстрый выигрыш через существующий ETL)
- Прогнать 1С-часть `scripts/import_month.py` против `ka_copy` за окно с данными
  (задать `IMPORT_ONEC_FROM`/`IMPORT_ONEC_TO`, напр. последний полный месяц ≥ окт.2025).
- ⚠️ `extract()` СЕЙЧАС связывает Bitrix+1С (сначала `bx_*`, потом `onec_*`). Для 1С-only:
  либо задать `BITRIX_WEBHOOK` (если Bitrix нужен), либо **выделить 1С-only путь** — переиспользуя
  `onec_window("Document_РеализацияТоваровУслуг", ...)` + `onec_by_key("Catalog_Номенклатура", ...)`
  из этого же файла, без Bitrix-вызовов. Затем `load-prices` (читает кэш `onec_sales`/`onec_sku`).
- Проверка: `python scripts/import_month.py verify` — счётчики SKU/цен выросли; в БД `Sku` и
  `StockItem.price` наполнены реальными кодами/названиями.
- Результат: подбор товара (`GET /sales/skus`) показывает реальную номенклатуру.

### Z3 — СЕБЕСТОИМОСТЬ из 1С (нужна живая база — исследуй OData сам)
- Найти регистр себеса: запросить корень OData и отобрать сущности по маске
  `*Себестоимость*` / `*СтоимостьТовар*` / `AccumulationRegister_*` (кандидаты:
  `AccumulationRegister_СтоимостьТоваров`, `..._СебестоимостьТоваров`, `..._ВыручкаИСебестоимостьПродаж`).
- Снять пример строки (`?$top=3&$format=json`), определить поля: ключ номенклатуры (`Номенклатура_Key`),
  сумма стоимости, количество, период, склад. **Себес единицы = Стоимость / Количество** за последний
  период на SKU (аналогично тому, как цена берётся из реализаций).
- Зафиксировать найденные имена сущности/полей в комментарии кода (как в `connectors/config.py`).

### Z4 — наполнить фасад `PriceCostGateway` (тогда маржа/провенанс оживают)
- Реализовать impl `PriceCostGateway.get_item_price_cost(session, sku_codes)`:
  `price_byn` — из `StockItem.price` (Z2) или расчёта; `cost_byn` — из себеса (Z3);
  `currency='BYN'`, `source='onec'`, `as_of` — дата актуальности. Нет данных по коду → не класть.
- Зарегистрировать: `core.services.price_cost = <impl>` в `IntegrationsModule.register()`
  (когда `onec_base_url` задан). Потребители в sales уже готовы — ничего в sales менять не надо.
- Проверить в CRM: карточка сделки показывает себес/цену с меткой **«из 1С»** (не «демо»).

### Z5 — живой `OneCClient` вместо mock (остатки/контрагенты)
- В `modules/integrations/client.py` заменить mock в `fetch_counterparties`/`fetch_stock` на реальные
  OData GET (по образцу `import_month`/`connectors/onec.py`), КОГДА `base_url` задан; пустой → mock
  (dev/тесты не ломать). Остальные mock-методы (`fetch_payments`/balances) — по возможности, но не
  обязательно для этой цели.

## 4. Ограничения (обязательно)
- **1С только чтение** — никакой записи (см. Z0-заголовок).
- **Не ломать существующее:** dev/тесты работают на mock (пустой `onec_base_url`). Полный `pytest`
  зелёный **до и после**. `ruff check .` чисто. Фронт-гейты (`tsc`/`lint`/`vitest`) если трогаешь фронт.
- **`alembic heads` == 1.** Миграции для цен/себеса добавлять только если реально нужна новая таблица
  (сначала попробовать наполнить существующие `Sku`/`StockItem`/справочник).
- **Секреты** (пароль 1С) — только `.env`/env стека на сервере, **никогда в git**.
- **Ветка/коммиты:** работать в СВОЕЙ ветке (`git worktree add ../_wt_1c-live -b sales-1c-live`),
  коммитить осмысленными шагами, **НЕ пушить без явной команды владельца**. Не трогать
  `frontend/src/lib/api.ts` (импорт — ок, правки — в split-файлы).
- `modules/sales` — потребители уже готовы; менять их НЕ требуется (только фасад наполнить).

## 5. Готово, когда (DoD)
- `curl .../odata/...` отвечает списком сущностей (доступ ✅).
- `python scripts/import_month.py verify` показывает реальные SKU и цены (не демо).
- В CRM: «Подбор товара» — реальные позиции; карточка сделки — себес/цена/маржа с меткой **«из 1С»**.
- Полный `pytest` зелёный; `ruff` чисто; `alembic heads` == 1.
- Найденные имена сущностей/полей себеса зафиксированы в коде-комментарии.

## 6. Подсказки/подводные камни
- OData 1С отдаёт GUID-ключи (`Ref_Key`, `Номенклатура_Key`); маппинг GUID→код — через
  `Catalog_Номенклатура` (`onec_by_key`). Заголовок Basic auth: `-u user:pass` или сессия с `.auth`.
- Для больших справочников — пагинация `$top/$skip`; `$orderby` обязателен для стабильного окна.
- Если номенклатуры много и не вся продаётся — товары можно брать не только из реализаций, но и прямым
  проходом `Catalog_Номенклатура` (код+название) для полного каталога подбора.
- Проверяй каждый шаг маленькими запросами (`$top=3`), прежде чем гонять полный проход.
