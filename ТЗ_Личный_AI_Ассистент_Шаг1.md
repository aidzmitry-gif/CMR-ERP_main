# ТЗ — Личный AI-ассистент, Шаг 1 (рабочее ядро на ноутбуке)

> Реализация Шага 1 из [Концепция_Личный_AI_Ассистент.md](Концепция_Личный_AI_Ассистент.md).
> Объём — **Средний MVP**: голос→структура + утренний план + Google Calendar + импорт/расшифровка записей.
> Всё локально на ноутбуке (Ryzen AI Max+ 395, Win 11 Pro). «Мозг» — Claude Code CLI headless на подписке.

**Статус:** ТЗ к разработке. **Дата:** 2026-06-15. **Владелец:** dtenergo.

---

## 1. Цель Шага 1 и границы

**Цель:** получить рабочего ассистента, которым можно пользоваться голосом каждый день:
надиктовал → структурировалось; утром пришёл план; записи разговоров расшифровываются и помнятся.

**В объёме (MVP):**
1. Telegram-бот: приём голоса/аудио/текста/пересланного.
2. Локальная транскрипция русской речи.
3. Структурирование через Claude Code (headless) → запись в Markdown-хранилище.
4. Утренний план по расписанию (с событиями Google Calendar).
5. Импорт и расшифровка записей: диктофон iFlytek SR101 (MTP) + фоновая запись на ноуте (2 дорожки).
6. Подготовка к созвону и вопросы к памяти (базовый Q&A по хранилищу).

**Вне объёма (позже):** корп. АТС/Asterisk; перенос в Postgres-модуль CRM (Шаг 2); цели/OKR (Шаг 3);
обзоры неделя/месяц как авто-push (в MVP — по запросу); онлайн-встречи Zoom/Meet как отдельный коннектор.

## 2. Архитектура (процессы и потоки)

Всё — локальные процессы на ноутбуке, под одним проектом `assistant/`.

```
                        ┌──────────────────────────────────────────────┐
   Telegram  ◄────────► │  bot.py  (long-polling, python-telegram-bot)  │
   (голос/текст)        │  приём voice/audio/text/forward, ответы        │
                        └───────────────┬──────────────────────────────┘
                                        │ ставит задачу в очередь
                                        ▼
            ┌───────────────────────────────────────────────────────┐
            │  worker  (обработка по одному сообщению)               │
            │  1) transcribe.py  — аудио → текст (локально)          │
            │  2) brain.py       — claude -p (headless) → JSON-намер.│
            │  3) store.py       — запись в Markdown-хранилище        │
            └───────────────────────────────────────────────────────┘
                                        ▲                    │
   ┌──────────────┐  cron/scheduler     │                    ▼
   │ scheduler.py │ ── утренний план ───┘            ┌────────────────┐
   │ (APScheduler)│ ── watcher SR101 ──►транскрипция │  data/ (Markdown│
   └──────┬───────┘ ── watcher записей─►транскрипция │  + шифрование)  │
          │                                          └────────────────┘
          ▼
   Google Calendar API (read-only)  ──►  события в утренний план
   recorder.py (фоновая запись 2 дорожки, по требованию)
```

**Принцип очереди:** бот не обрабатывает синхронно — кладёт задачу, worker берёт по одной
(транскрипция/`claude -p` не мгновенны). MVP-реализация очереди — простая (файловая или in-process),
без брокера. `# ponytail: in-process queue, заменить на Redis/RQ если поток вырастет`.

## 3. Хранилище (Markdown, на зашифрованном диске)

```
assistant/
├── data/                      # ← под BitLocker/VeraCrypt
│   ├── projects/<slug>.md     # проект: статус, цель, задачи, последнее движение
│   ├── people/<slug>.md       # человек: роль, договорённости, вопросы «спросить»
│   ├── ideas/inbox.md         # входящие идеи (список)
│   ├── tasks.md               # единый список задач (front-matter + строки)
│   ├── calls/YYYY-MM-DD-<кто>.md   # расшифровка + извлечённые договорённости
│   ├── daily/YYYY-MM-DD.md    # план дня / итог дня
│   └── audio/                 # сырые аудио (wav), временно до расшифровки
├── config.toml                # токены, пути, расписание, выбор модели
├── prompts/                   # системные промпты для claude -p (структуризатор, саммари звонка…)
└── *.py                       # модули (см. §2)
```

**Формат файлов** — Markdown с YAML-front-matter для машиночитаемых полей. Пример `tasks.md`:
```markdown
- [ ] Закрыть модуль доступа (CRM) <!-- proj:crm due:2026-06-19 prio:high src:voice-0615 -->
- [x] Созвон с Иваном (склад)       <!-- proj:crm done:2026-06-15 -->
```
Пример `people/ivan.md` — секции `## Договорённости`, `## Спросить`, `## История`.
Машинные поля в HTML-комментариях/front-matter — чтобы и человек читал, и парсер брал.

## 4. Функциональные блоки и критерии готовности

> Порядок = порядок реализации (по ценности). Каждый блок — самостоятельно проверяемый.

### Блок A. Telegram-бот (каркас)
- **Что:** long-polling бот; команды `/start`, `/help`; приём voice, audio-файл, text, forward, фото (фото — задел, OCR позже).
- **Делает:** сохраняет входящее (аудио→`data/audio/`), ставит задачу в очередь, отвечает «принял, обрабатываю».
- **Готово, когда:** отправил голосовое → бот подтвердил приём, файл лёг в `data/audio/`.

### Блок B. Локальная транскрипция (`transcribe.py`)
- **Что:** аудио (ogg/opus из TG, wav/aac с диктофона) → текст. Конвертация через ffmpeg → wav 16кГц моно.
- **Модель (по §6а концепции):**
  - основной русский — **GigaAM-v3** (встречи/диктовка) или **T-one** (телефония); выбрать на бенчмарке твоего аудио;
  - фолбэк/мультиязык — **faster-whisper / whisper.cpp на Vulkan**.
  - `# ponytail: старт на faster-whisper (ставится без боли), GigaAM/T-one добить после бенчмарка точности RU`.
- **Готово, когда:** голосовое на русском → корректный текст в логе; время обработки приемлемо (цель < длительности×2).

### Блок C. «Мозг» — структуризатор (`brain.py`)
- **Что:** вызывает `claude -p "<system+входной текст>" --output-format json` (headless, на подписке).
- **Системный промпт** (`prompts/structurer.md`): на вход — расшифрованный текст; на выход — **строгий JSON**
  с намерением и действиями:
  ```json
  {"intent":"task|idea|agreement|done|project|question|note",
   "actions":[{"op":"add_task","project":"crm","text":"...","due":"2026-06-19","prio":"high"}],
   "reply":"короткое подтверждение пользователю",
   "needs_clarification": null }
  ```
- **Неоднозначность:** если модель не уверена — `needs_clarification:"к какому проекту отнести?"` → бот
  переспрашивает (не гадает). См. сценарий §2.2 концепции.
- **Готово, когда:** фраза «по CRM закрыть модуль доступа к пятнице» → валидный JSON с `add_task`,
  правильным проектом и `due`.
- **Фолбэк-мозг:** тот же контракт JSON, но через Ollama (Qwen3-35B) — флаг в `config.toml`.
  `# ponytail: claude -p основной; ollama-ветка — для оффлайна/сверх-чувствительного`.

### Блок D. Запись в хранилище (`store.py`)
- **Что:** применяет `actions` из JSON к Markdown-файлам (add_task, add_idea, add_agreement, mark_done,
  upsert_project, add_question). Идемпотентно, с защитой от дублей.
- **Готово, когда:** после A→B→C→D задача реально появилась в `tasks.md` с верными полями, бот прислал `reply`.

### Блок E. Утренний план (`scheduler.py` + Google Calendar)
- **Что:** APScheduler, ежедневно в 08:00 (время в config). Собирает: задачи на сегодня (по `due`/prio),
  события Google Calendar, «изучить», зависшие хвосты, число идей в инбоксе → формирует план → шлёт в TG.
- **Google Calendar:** OAuth desktop-flow, scope read-only; токен — локально, зашифрован.
- **Готово, когда:** в назначенное время (и по команде `/plan`) приходит план дня с реальными событиями календаря.

### Блок F. Импорт и расшифровка записей
- **F1. Диктофон iFlytek SR101 (проверен, §6б концепции):** watcher — при подключении MTP-устройства `SR101`
  забирает новые `.wav` через COM `Shell.Application` (не Get-ChildItem!) → `data/audio/` → транскрипция (Блок B)
  → саммари звонка через Claude (`prompts/call_summary.md`) → `data/calls/` + договорённости в `people/`.
- **F2. Фоновая запись на ноуте (2 дорожки):** `recorder.py` — микрофон + системный звук (WASAPI loopback,
  PyAudioWPatch/SoundCard) раздельно; старт/стоп по команде в TG (`/rec_start`, `/rec_stop`). По стопу →
  тот же конвейер транскрипции+саммари. Раздельные дорожки → разметка «ты vs собеседник».
- **Готово, когда:** (F1) подключил диктофон → новая запись сама расшифровалась и саммари пришло в TG;
  (F2) `/rec_start`…`/rec_stop` → получил расшифровку с разделением говорящих.

### Блок G. Подготовка к созвону + Q&A по памяти
- **Что:** `/prep <имя>` → собирает из `people/<имя>.md` и `calls/` открытые договорённости, просрочки,
  вопросы «спросить». Свободный вопрос («что я обещал Ивану») → `claude -p` с подгрузкой нужных файлов → ответ.
- **Готово, когда:** `/prep Иван` даёт досье; вопрос к памяти возвращает осмысленный ответ из хранилища.

## 5. Нефункциональные требования

- **Приватность:** аудио и расшифровки **не покидают ноут**; наружу (Claude Code) уходит только **текст**.
  Сверх-чувствительное — через Ollama-ветку (ничего не уходит). Голос на диктофоне/в TG → сразу локально.
- **Безопасность хранения:** `data/` на зашифрованном диске (BitLocker/VeraCrypt) — **включить до записей**.
  Токены (Telegram, Google) — в `config.toml` вне git, права только владельцу.
- **Надёжность:** worker переживает падение задачи (одна ошибка не роняет очередь); аудио не удаляется до
  успешной расшифровки; при сбое `claude -p` — повтор, затем уведомление в TG.
- **Язык:** интерфейс и промпты — русский; модель транскрипции — русская (RU-приоритет).
- **Стиль кода:** лестница лени (CLAUDE.md) — минимум кода, stdlib/готовые либы, без абстракций «про запас».

## 7. Порядок сборки (вехи)

1. **Веха 1 — «говорю → структурируется»:** A + B(faster-whisper) + C(claude -p) + D.
   *Результат:* надиктовал задачу — она в `tasks.md`, бот подтвердил. Это уже полезно.
2. **Веха 2 — «утро само приходит»:** E (план + Google Calendar).
3. **Веха 3 — «помнит разговоры»:** F1 (диктофон) + F2 (фоновая запись) + саммари в `calls/`.
4. **Веха 4 — «готовит к встрече»:** G (prep + Q&A).
5. **Шлифовка:** RU-модель (GigaAM/T-one) вместо whisper по бенчмарку; формат утреннего плана на реальных данных.

Каждая веха — самостоятельно работающий инкремент; после Вехи 1 ассистентом уже можно пользоваться.

## 9. Критерий готовности Шага 1 (Definition of Done)

Шаг 1 готов, когда одновременно:
1. Голосовое в TG на русском → корректная структура в нужном файле + подтверждение бота.
2. Каждое утро (и по `/plan`) приходит план дня с событиями Google Calendar.
3. Запись с диктофона SR101 при подключении → авто-расшифровка + саммари с договорённостями.
4. Фоновая запись (`/rec_start`…`/rec_stop`) → расшифровка с разделением говорящих.
5. `/prep <имя>` → досье к созвону; вопрос к памяти → осмысленный ответ.
6. Аудио и расшифровки лежат локально на зашифрованном диске; наружу уходит только текст.
