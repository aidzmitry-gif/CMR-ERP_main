# Настройка 1С для подключения по OData (инструкция администратору)

> Документ для администратора сервера 1С. Цель — дать внешней системе доступ
> **только на чтение** к данным 1С через штатный интерфейс **OData**, чтобы
> сервис сбора данных мог инкрементально выгружать справочники/документы.
> Запись в 1С не выполняется. Требуется платформа **1С:Предприятие 8.3.5+**.

---

## 0. Что в итоге нужно прислать заказчику

После настройки пришлите три вещи (пароль — по защищённому каналу, не в почте/мессенджере открытым текстом):

1. **Базовый URL OData**, вида
   `http://<сервер>/<имя-публикации>/odata/standard.odata/`
   (или `https://…`, если настроен TLS).
2. **Логин и пароль** созданного служебного пользователя 1С (HTTP Basic).
3. **Список имён наборов сущностей**, которые открыты в составе OData
   (например `Catalog_Контрагенты`, `Document_РеализацияТоваровУслуг`).
   Их видно по адресу `…/odata/standard.odata/$metadata`.

Эти значения попадут в конфигурацию сервиса (`ONEC_BASE_URL`, `ONEC_USER`,
`ONEC_PASSWORD`, и состав объектов).

---

## 1. Опубликовать информационную базу на веб-сервере

OData работает только через веб-публикацию ИБ (модуль расширения веб-сервера —
**Apache** или **IIS** на машине с 1С).

1. Установить веб-сервер (Apache 2.4 или IIS) и компоненту «Модули расширения
   веб-сервера» из дистрибутива платформы 1С (если ещё не стоит).
2. Открыть базу в **Конфигураторе** → меню **Администрирование →
   Публикация на веб-сервере…**.
3. Задать **имя публикации** (латиницей, напр. `base`) — оно станет частью URL.
4. **Включить флажок «Публиковать стандартный интерфейс OData»** (ключевой пункт).
5. Опубликовать. Платформа создаст каталог публикации и файл `default.vrd`.

После этого базовый адрес OData:
`http://<сервер>/<имя-публикации>/odata/standard.odata/`

---

## 2. Задать состав интерфейса OData (какие объекты видны)

По умолчанию интерфейс **пуст** — ни один объект не отдаётся, пока его явно не
включили в состав. Делается один раз.

**Способ А (режим 1С:Предприятие):**
- Запустить базу в режиме 1С:Предприятие под администратором.
- **Главное меню → Все функции → Стандартный интерфейс OData →
  Настройка состава стандартного интерфейса OData.**
  (Если пункта «Все функции» нет — включить в *Сервис → Параметры → отображать
  команду «Все функции»*.)
- Отметить нужные объекты (см. §3) и записать состав.

**Способ Б (программно):** вызвать `SetODataInterfaceContent`/
`УстановитьСоставСтандартногоИнтерфейсаOData` — если у вас принят такой регламент.

> Изменение состава не требует перепубликации, но иногда нужен сброс кэша
> веб-сервера / перезапуск рабочих процессов, чтобы `$metadata` обновился.

---

## 3. Какие объекты открыть (минимально необходимое, read-only)

Открывайте **только то, что реально нужно выгружать** — принцип наименьших
привилегий. Типичные кандидаты для базы знаний (уточните у заказчика финальный
список):

| Тип объекта 1С | Префикс набора в OData | Пример |
|---|---|---|
| Справочник | `Catalog_<Имя>` | `Catalog_Контрагенты`, `Catalog_Номенклатура` |
| Документ | `Document_<Имя>` | `Document_РеализацияТоваровУслуг` |
| Регистр накопления | `AccumulationRegister_<Имя>` | `AccumulationRegister_Продажи` |
| Регистр сведений | `InformationRegister_<Имя>` | `InformationRegister_ЦеныНоменклатуры` |

- Имена могут быть кириллическими — это нормально, в URL они кодируются.
- Поле ключа у большинства объектов — `Ref_Key`.
- У документов есть поле даты (часто `Date`) — оно нужно сервису для
  инкрементальной выгрузки (тянуть только новое/изменённое).

---

## 4. Создать служебного пользователя (только чтение)

Не используйте администратора. Заведите отдельного пользователя для интеграции.

1. Конфигуратор → **Администрирование → Пользователи → Добавить**.
   - Имя, например, `odata_user`.
   - **Аутентификация 1С:Предприятия** — включить, задать пароль
     (нужно для HTTP Basic; доменная/ОС-аутентификация для этого сценария не подходит).
   - Снять «Пользователю запрещено изменять пароль» по вашему регламенту.
2. **Роли**: дать роль(и), дающие **только право «Чтение»** на объекты из §3.
   - Если подходящей роли нет — создать отдельную роль (напр. `ИнтеграцияOData_Чтение`)
     с правом «Чтение» (и «Просмотр») на нужные объекты, без «Добавление/
     Изменение/Удаление/Проведение».
   - Учтите RLS (ограничение на уровне записей), если оно есть, — OData его соблюдает.
3. Не выдавать «Полные права», «Администрирование», запуск Конфигуратора.

---

## 5. Безопасность (важно)

- **Только чтение** — у пользователя не должно быть прав на изменение данных.
- **Сеть**: не выставляйте OData-эндпоинт в открытый интернет. Доступ — из
  внутренней сети / через VPN (например Tailscale). Ограничьте порт веб-сервера
  файрволом до адреса хоста-сборщика.
- **TLS**: по возможности опубликуйте по `https://` (сертификат на веб-сервере),
  чтобы Basic-логин/пароль не шли открытым текстом.
- Пароль служебного пользователя передайте заказчику защищённым каналом.

---

## 6. Проверка (выполнить администратору перед отправкой доступов)

С машины, где есть сетевой доступ к веб-серверу 1С. Замените URL/логин/пароль.

**Метаданные (список открытых наборов сущностей):**
```bash
curl -u "odata_user:ПАРОЛЬ" \
  "http://<сервер>/<публикация>/odata/standard.odata/\$metadata?\$format=json"
```
Ожидаемо: JSON/XML со списком `EntitySet` — это и есть имена объектов для §0.3.

**Пробная выборка одной записи справочника:**
```bash
curl -u "odata_user:ПАРОЛЬ" \
  "http://<сервер>/<публикация>/odata/standard.odata/Catalog_Контрагенты?\$top=1&\$format=json"
```
Ожидаемо: HTTP 200 и JSON с полем `value: [ { … "Ref_Key": "…" } ]`.

Если возвращается:
- **401** — проблема аутентификации (проверьте, что у пользователя включена
  аутентификация 1С:Предприятия и верный пароль; что публикация разрешает Basic).
- **404 на объекте, но `$metadata` пуст/без него** — объект не включён в состав
  OData (вернитесь к §2).
- **404 на самом `/odata/standard.odata/`** — не включён флажок публикации OData
  (§1.4) или не перезапущен веб-сервер.

---

## 7. Заметки для интеграции (передать вместе с доступами)

- Сервис обращается к методам OData с параметрами `$format=json`, `$top`, `$skip`,
  `$orderby`, опционально `$select` и `$filter` — всё **только чтение** (GET).
- Для инкремента по дате сервис строит фильтр вида
  `<ПолеДаты> gt datetime'<значение>'`. **Синтаксис литерала даты в `$filter`
  может зависеть от версии платформы** — если фильтрация по дате даёт ошибку,
  сообщите версию платформы 1С (например 8.3.21), скорректируем формат.
- Никаких изменений в 1С со стороны сервиса не происходит; нагрузка — периодические
  GET-запросы небольшими страницами.

---

### Краткий чек-лист администратору

- [ ] ИБ опубликована на веб-сервере, включён флажок «Публиковать стандартный интерфейс OData» (§1)
- [ ] В состав OData включены нужные объекты (§2–§3)
- [ ] Создан служебный пользователь с аутентификацией 1С и правом **только чтение** (§4)
- [ ] Доступ к эндпоинту ограничен сетью/VPN, по возможности TLS (§5)
- [ ] `curl` на `$metadata` и на одну запись возвращает 200 (§6)
- [ ] Заказчику отправлены: базовый URL, логин/пароль (защищённо), список имён наборов сущностей (§0)
