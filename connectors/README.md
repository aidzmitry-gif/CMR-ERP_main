# Коннекторы сбора данных (1С · Bitrix24 · Google)

Слой «сбор» для гибридной RAG-базы. Тянет данные из источников инкрементально
и складывает нормализованные записи в `data/inbox/` (по файлу на запись), а
записи звонков — в `data/media/`. Дальше эту очередь забирает воркер
ASR → LLM-куратор → эмбеддинг → Qdrant.

Свойства: инкремент по курсору, идемпотентность (повторный прогон безопасен),
ретраи с экспоненциальной паузой, мягкое соблюдение лимитов Bitrix.

## Что нужно по доступам

### Bitrix24 (облако)
1. Создать **входящий вебхук**: Разработчикам → Другое → Входящий вебхук.
2. Права вебхука: `telephony` (звонки), `crm` (сделки/контакты/компании),
   `user`, `disk` (скачивание файлов записей).
3. У пользователя вебхука должно быть право «Статистика звонков — Просмотр».
4. URL вебхука целиком положить в `BITRIX_WEBHOOK`.
> Записи в облаке съедают квоту диска портала и могут ротироваться — запустите
> бэкофилл по 1000+ звонкам как можно раньше, ежедневный сбор держите актуальным.

### 1С (OData)
1. Опубликовать **стандартный интерфейс OData** на веб-сервере 1С
   (URL вида `http://server/base/odata/standard.odata/`).
2. Завести пользователя 1С с правами на чтение нужных объектов (HTTP Basic).
3. В `config.py` заполнить `ONEC_ENTITY_SETS` — какие именно объекты тянуть
   (зависит от вашей конфигурации: справочники, документы, регистры).

### Google (Docs + Sheets)
1. В Google Cloud создать проект и включить **Drive API, Docs API, Sheets API**.
2. Создать **сервисный аккаунт** и скачать JSON-ключ → путь в `GOOGLE_CREDENTIALS_FILE`.
3. Дать доступ к данным одним из способов:
   - расшарить нужные папки/файлы на e-mail сервисного аккаунта, **или**
   - включить domain-wide delegation и указать `GOOGLE_IMPERSONATE`.
4. ID папок Drive (из URL папки) перечислить в `GOOGLE_FOLDER_IDS`.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить значениями
```

## Запуск

```bash
python -m connectors.run              # все источники
python -m connectors.run bitrix       # только Bitrix24
python -m connectors.run onec google  # 1С и Google
```

Для фонового режима повесьте на таймер/демон: ежедневный сбор + добор бэкофилла.
Курсоры хранятся в `data/state.json`, поэтому каждый запуск продолжает с места.

## Формат вывода

Каждая запись — JSON по схеме `RawRecord` (`models.py`):

```json
{
  "source": "bitrix_call",
  "source_id": "12345",
  "record_type": "call",
  "payload": { "...": "сырые поля источника" },
  "fetched_at": "2026-06-10T12:00:00+00:00",
  "media_path": "data/media/call_12345.mp3",
  "source_url": "https://..."
}
```

`unit_id` = `source:source_id` — сквозной ключ для дедупа и upsert в Qdrant.

## Что доработать под себя
- `ONEC_ENTITY_SETS` — перечень объектов 1С (обязательно).
- Скачивание записи в `bitrix.py` (`_download_record`): имя поля с прямой
  ссылкой может отличаться от портала; фолбэк через `disk.file.get` уже заложен.
- Синтаксис фильтра по дате в `onec.py` может зависеть от версии платформы 1С.
