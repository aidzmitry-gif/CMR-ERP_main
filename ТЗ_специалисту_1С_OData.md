# Техническое задание специалисту 1С
## Открыть доступ к данным по OData (только чтение) для внешней системы

---

## 1. Что уже сделано (контекст)

- База — **1С:Комплексная автоматизация для Беларуси, ред. 2.4** (2.4.14.182), платформа **8.3.18.1661**, **серверный режим** (Srvr=localhost, Ref=ka_copy).
- Опубликована на **IIS** под именем `ka_copy` (каталог `C:\inetpub\wwwroot\ka_copy\`). В публикации включён флажок «Публиковать стандартный интерфейс OData».
- Сервис OData **отвечает**: по адресу `http://localhost/ka_copy/odata/standard.odata/` возвращается корректный XML, ошибок нет.

## 2. Проблема, которую нужно решить

- **Состав стандартного интерфейса OData пуст** — в ответе сервиса нет ни одной коллекции (`<workspace>` без `<collection>`). Из-за этого внешняя система не может выгрузить ни одного объекта.
- Самостоятельно открыть состав не удалось: команда «Состав стандартного интерфейса OData…» в меню Конфигуратора недоступна — предположительно потому, что **конфигурация на поддержке** (замок у корня конфигурации) и не включена возможность изменения.
- **Важно:** файл `default.vrd` уже приведён в рабочее состояние (`<standardOdata enable="true" .../>` самозакрывающийся). Через `.vrd` состав на платформе 8.3.18 не задаётся (платформа отвергает вложенные элементы) — состав нужно открыть штатно из Конфигуратора / режима Предприятие.

## 3. Задача 1 — открыть состав OData

Включить в состав стандартного интерфейса OData перечисленные ниже объекты (**только чтение**). Порядок приоритета — сверху вниз; минимально обязателен п.1 (Контрагенты).

**Способ А — режим 1С:Предприятие (предпочтительно):**
1. Запустить базу `ka_copy` в режиме 1С:Предприятие под пользователем с полными правами.
2. Главное меню → **Все функции** → **Стандартный интерфейс OData** → **Настройка состава стандартного интерфейса OData**. (Если «Все функции» не видно — включить в Сервис → Параметры → «Отображать команду «Все функции»».)
3. Отметить объекты из таблицы ниже → **Записать**.

**Способ Б — Конфигуратор (если нужен этот путь):**
1. Конфигурация → Поддержка → **Настройка поддержки** → **Включить возможность изменения** (изменения объектов конфигурации НЕ требуются — только разблокировать команду).
2. Меню **Администрирование** → **Состав стандартного интерфейса OData…** → отметить объекты → ОК.

**Объекты для включения в состав OData:**

| № | Объект 1С | Назначение |
|---|-----------|------------|
| 1 | Справочник «Контрагенты» | Клиенты — обязательный первый шаг (связка с CRM по УНП) |
| 2 | Справочник «Контактные лица» | Сотрудники контрагентов |
| 3 | Справочник «Договоры контрагентов» | Договоры клиентов |
| 4 | Справочник «Номенклатура» | Товары/услуги (карточка: вес, код ТНВЭД, группы) |
| 5 | Документ «Реализация товаров и услуг» (+ табл. часть «Товары») | История покупок: что/когда/на какую сумму |
| 6 | Документ «Заказ клиента» (+ «Товары») | Заказы клиентов |
| 7 | Документ «Счёт на оплату клиенту» | Счета |
| 8 | Регистр «Расчёты с клиентами» (или аналог дебиторки в КА 2.4) | Деньги / дебиторская задолженность |
| 9 | Регистр сведений «Цены номенклатуры» | История цен |
| 10 | Документ «Сборка (разборка) товаров», справочник «Ресурсные спецификации» | Сборки/комплектация под клиента (если ведутся) |

Если каких-то объектов в этой конфигурации нет под такими именами — включить ближайшие аналоги и сообщить заказчику фактические имена. **Минимум для старта — «Контрагенты».**

## 4. Задача 2 — служебный пользователь (только чтение)

Не использовать администратора. Завести отдельного пользователя для интеграции:
- Имя, например, `odata_user`.
- **Аутентификация 1С:Предприятия** — включить, задать пароль (нужно для HTTP Basic; доменная/ОС-аутентификация для коннектора не подходит).
- **Роли — только чтение** на объекты из раздела 3: право «Чтение»/«Просмотр», **без** «Добавление/Изменение/Удаление/Проведение». При отсутствии подходящей роли — создать роль `ИнтеграцияOData_Чтение`.
- НЕ выдавать: «Полные права», «Администрирование», запуск Конфигуратора.
- Учесть RLS (ограничения на уровне записей), если есть, — OData их соблюдает.

## 5. Проверка перед сдачей

С машины, где есть доступ к веб-серверу 1С (подставить логин/пароль):

```
curl -u "odata_user:ПАРОЛЬ" "http://localhost/ka_copy/odata/standard.odata/$metadata?$format=json"
```
Ожидаемо: список `EntitySet` с включёнными объектами (напр. `Catalog_Контрагенты`).

```
curl -u "odata_user:ПАРОЛЬ" "http://localhost/ka_copy/odata/standard.odata/Catalog_Контрагенты?$top=1&$format=json"
```
Ожидаемо: HTTP 200 и JSON с записью контрагента (поле `Ref_Key`).

После изменения состава может потребоваться `iisreset` (PowerShell от администратора), чтобы `$metadata` обновился.

## 6. Что прислать заказчику по итогу

Пароль — по защищённому каналу, не открытым текстом в почте/мессенджере.
1. **Базовый URL OData**: `http://<сервер>/ka_copy/odata/standard.odata/` (или внутренний/VPN-адрес).
2. **Логин и пароль** служебного пользователя 1С.
3. **Список фактически открытых имён наборов сущностей** (как называются в `$metadata`).
4. **Версию платформы** (8.3.18.1661) — для корректного синтаксиса фильтра по дате при инкрементальной выгрузке.

## 7. Безопасность

- **Только чтение** — у пользователя не должно быть прав на изменение.
- Эндпоинт OData **не выставлять в открытый интернет**: доступ из внутренней сети / через VPN (у заказчика настроен Tailscale, адрес сервера `100.75.171.85`).
- По возможности — **https** (TLS на веб-сервере), чтобы Basic-логин/пароль не шли открытым текстом.

---

*Никаких изменений данных со стороны внешней системы не происходит — только периодические GET-запросы небольшими страницами.*
