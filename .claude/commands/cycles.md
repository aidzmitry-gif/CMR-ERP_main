Мандат на циклы улучшений: $ARGUMENTS

Действуй строго по контракту (он заменяет свободную трактовку «сделай N циклов»):

1. **Прочитай `PLAN.md`** в корне проекта (если есть). Это стейт-файл циклов между
   сессиями: НЕ анализируй модуль заново, если там уже есть картирование и план —
   продолжай с первого невыполненного пункта.
2. **Составь нумерованный план**: по каждому циклу — цель, файлы, критерий готовности.
   Кандидатов бери из анализа модуля + невыполненного из PLAN.md. Запиши план в PLAN.md
   (секция с датой).
3. **Утверди состав одним AskUserQuestion**: список кандидатов (multiSelect) + критерий
   остановки. БЕЗ утверждения реализацию не начинать. Если в плане есть развилка дизайна —
   новый UI-элемент управляет тем же, чем существующий; вторая однотипная панель;
   чувствительные данные в вёрстке — добавь её в этот же вопрос.
4. **Работай циклами по skill `ship-cycle`** (гейты → коммит → ревью-субагент).
5. **Чек-пойнт после каждых 2 циклов**: одно короткое сообщение — что сделано, что
   дальше, «продолжаю/стоп?» через AskUserQuestion. Не работай «пока нечего будет
   улучшать» без утверждённого критерия остановки.
6. После каждого цикла отмечай в PLAN.md статус пункта (✓/отложено/отменено — с одной
   строкой почему). Решения по развилкам — в `coordination/DECISIONS.md` (дата + тег).
