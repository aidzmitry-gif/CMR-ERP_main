# html-first — прототип до кода

Самая дешёвая итерация по самым дорогим-в-изменении решениям (UX/флоу/скоуп) — в HTML, а не
в собранной React+FastAPI-фиче. Прототип = исполняемый спек: снимает неоднозначность лучше
текстового ТЗ и вскрывает бэкенд-контракт (какие данные/события/права нужны) ДО дорогой стройки.

**Когда применять:** новая или нетривиальная UX, новый экран/флоу, редизайн.
**Когда НЕ применять:** правка в 1-2 экрана / 10 строк — там прототип = оверкилл (лестница лени).

## Поток (2 гейта)
```
HTML-мокап (честный, decision-fidelity)
   → GATE 1: оператор говорит «хорошо» (продукт/UX)
   → GATE 2: чек осуществимости + контракт данных (техника)
   → реализация СЛАЙСАМИ по флоу (порт разметки, не throwaway)
```
Один гейт (только одобрение) недостаточен: можно одобрить красивую UX для **заблокированной**
способности. Второй гейт это ловит.

## GATE 1 — продукт/UX (одобряет оператор)
- [ ] Все окна экрана/флоу нарисованы, переходы между ними кликабельны.
- [ ] Кнопки/действия показывают НАМЕРЕНИЕ (что произойдёт), даже если данные фейковые.
- [ ] Состояния показаны: пусто/загрузка/ошибка/успех (не только «happy path»).
- [ ] Оператор явно сказал «хорошо, можно работать». Без этого — на реализацию НЕ идём.

## GATE 2 — осуществимость + контракт данных (техника, перед стройкой)
- [ ] Какие РЕАЛЬНЫЕ данные нужны каждому окну? Откуда (1С/MDM/модуль/событие)?
- [ ] Бэкенд-способность есть или это **блокер**? (сверь: методика цены, запись в 1С заморожена,
      нужные события в `DEPENDENCY-MAP §2`, MDM-шов). Полированная UX для блокера = долг.
- [ ] Какие события шины эмитить/слушать? Новое событие → обновить `DEPENDENCY-MAP §2` (через координатора).
- [ ] Права/RBAC: какие `require_permission`? Деньги — Decimal, валюта BYN.
- [ ] Нужна миграция? → `scripts/next_migration.py` (через координатора).
- [ ] Скоуп нарезан на флоу (не «весь модуль разом») — первая ценность раньше, петля обратной связи короче.

## Реализация
- Порт разметки HTML→React (не выбрасывай мокап — переиспользуй структуру/классы; так двойная работа минимальна).
- Слайсами: один флоу → реализация → следующий. Не big-bang весь модуль.
- Перед мержем — `python scripts/lane_check.py <lane>` + DoD (`coordination/DoD.md`).

## Честный мокап (обязательно)
Мокап ОБМАНЫВАЕТ, если прячет, что реально, а что demo. Правила и шаблон — `references/honest-mockup.md`:
помечай real-vs-demo (бейдж провенанса `<SourceTag>`/honest-empty), фиделити под РЕШЕНИЕ (не пиксель-перфект),
не полируй то, что может не пройти Gate 2.

## Связь с флотом
Полоса может стартовать от ОДОБРЕННОГО прототипа: скилл `lane-onboard` засевает полосу, в «Следующий шаг»
кладётся «реализовать одобренный мокап `<файл>.html` по флоу X». HTML-first = «проверяй до того как строить»
на уровне продукта; Gate 2 = тот же verify-before-build на уровне данных/контракта.
