# AGENTS.md — канон для не-Claude агент-сессий (Codex и др.)

> В этом репо параллельно работает флот Claude Code-сессий со своим координационным
> слоем (`coordination/`, git-хуки, реестры). Ты его не видишь, поэтому синхронизация —
> только через git. Правила ниже обязательны. Полный канон архитектуры — `CLAUDE.md`
> (разделы «Как добавить/менять модуль», «Данные и транзакции», «Лестница лени»).

## Git-дисциплина (критично)

1. **Работай ТОЛЬКО на своих ветках `agent/*`.** Интеграция — только через PR.
2. **НИКОГДА не коммить напрямую** в `main` и `sales-2.0-redesign` — это общие ветки,
   в них пишут несколько сессий; прямой коммит затрёт чужую работу.
3. **Никаких `--amend` / `reset` / `rebase` / force-push на общих ветках.**
   На своей `agent/*` — можно.
4. **Мерж PR в общие ветки — только по явному разрешению оператора.**
   Открывать PR (draft) можно всегда. Новые ветки — от свежего `origin/<общая ветка>`.
5. **Submodules:** 9 модулей в `modules/*` — отдельные репозитории (`.gitmodules`).
   Правка модуля = коммит в его репо + bump gitlink в суперпроекте.
   **Сначала пушь ветку сабмодуля, потом суперпроект** — иначе CI падает на
   checkout («not our ref»; прецедент 2026-07-04, `modules/sales`).

## Не трогать (владение других полос)

- `config/settings.py`, `config/modules.py`, `core/services/__init__.py`,
  `core/db/base.py` — файлы-хотспоты; правки только через оператора.
- `.claude/**`, `coordination/**` — служебные каталоги флота Claude.
- Миграции Alembic: номера резервируются между сессиями — нужна миграция?
  СНАЧАЛА спроси у оператора номер. Всегда ровно один head (`alembic heads` перед PR).

## Разделение труда (обновлено 2026-07-18, решение оператора)

**Твоя зона — ТОЛЬКО деплой на сервер** (то, чего Claude-флот физически не может: SSH/Docker/сервер;
гвард блокит `tailscale ssh`/prod-IP во всех Claude-сессиях):
- Размещение проекта и изменений на сервере `/opt/cmr-erp` (`git pull --recurse-submodules` /
  `deploy-belakb.sh` / `docker compose up -d --build`).
- Около-ops: env/секреты, secure-env, Keycloak/OIDC-инфра, применение миграций на сервере, смоук,
  откат, Caddy/порты, подключение 1С на сервере.
- Дисциплина: пуш в `origin/main` ДО деплоя (git = истина прода); снять точку отката ДО pull;
  один alembic head на сервере после деплоя.

**ВЕСЬ КОД (backend/frontend/фиксы/фичи/тесты) ведёт Claude-флот, не ты.** Не открывай PR с кодом
и не правь модули без явной просьбы оператора. Синхронизация через git: Claude мержит проверенное
в `main` → ты выкатываешь. Твой канал в координацию — описание PR деплоя / строка оператору.

## Отчётность

Итог сессии — в описании PR: что сделано, какие файлы, чем верифицировано
(тесты/линт/типы). PR-описание — твой единственный канал в координацию флота.

## Гейты CI (блокирующие)

- Backend: `ruff check .`, `alembic upgrade head` (Postgres), `pytest --cov-fail-under=90`.
- Frontend: `tsc --noEmit`, `eslint` с храповиком `--max-warnings` (потолок в
  `.github/workflows/ci.yml` — только опускать, новые предупреждения не проходят),
  Vitest + RTL, Playwright E2E.

## Технические гочи проекта

- Путь содержит пробелы и кириллическую «С» в «Сlaude» — всегда бери пути в кавычки.
- PowerShell 5.1 портит UTF-8 при `Get-Content`/`Set-Content` round-trip — кириллические
  файлы правь точечными diff-правками, не перезаписью целиком.
- Локальный dev без Docker — SQLite (`AIOS_DATABASE_URL=sqlite+aiosqlite:///./dev.db`);
  схема Postgres — только через Alembic. Vitest гоняй локальным бинарём
  (`npm run test:run`), не `npx vitest`.
